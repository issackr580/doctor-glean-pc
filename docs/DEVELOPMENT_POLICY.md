# 의사 이삭 줍기 PC 개발 방침

2026년 10월 26일 한국 시간 기준. Windows PC를 켜두고 사용하는 사람을 위한 독립형 상주 프로그램으로 개발한다. 정기 서버 운영비가 발생하는 구성을 사용하지 않는다. PC판과 Android판은 각자 로그인하고 각자 실행한다.

## 확정한 제품 범위

| 항목 | 방침 |
| --- | --- |
| 지원 환경 | Windows 우선. 첫 실기기 검증은 Windows 11 x64를 기준으로 하고, Windows 10 호환은 별도 확인한다. Mac은 이번 구현 범위에 포함하지 않는다. |

## 개발자용과 배포용

두 버전의 강의 조회·출석·입장 기능 목표는 같다. 개발자용은 지정 collaborator의 검증용이며, 배포용만 일반 공개 대상이다. `preview`는 검증 단계 표시이며 개발자용·배포용의 구분은 별도의 빌드 설정으로 고정한다.

상호 계정·로그인 쿠키·설정·결과를 복사하지 않는다. 각 버전은 한 프로세스만 실행하며, 버전 사이의 중복 실행은 안내로 처리한다. 과거 공통 검증본의 데이터를 자동으로 이관하지 않는다. 추가 진단은 앱 주 프로세스의 수치만 기록하며 자동 전송하지 않는다. 연결 정책 점검은 오프라인 정책 확인이며 OS·실제 사이트 보안 검증을 대신하지 않는다.

## 기술과 보안

Electron과 기존 JavaScript 판독 엔진을 사용한다. 큰 대시보드나 브라우저 확장 설치 없이 작은 관리 창과 트레이를 제공한다. 첫 개발 의존성은 공식 배포와 npm에서 확인한 Electron 45.0.0으로 고정하며, 배포 전 지원·보안 수정 상태를 다시 확인한다. 패키지 잠금 파일을 보관한다.

관리 창은 로컬 파일만 표시한다. 사이트 창은 Node 접근을 끄고 sandbox와 contextIsolation을 켠다. 관리 창의 좁은 API를 사이트나 하위 프레임에 노출하지 않는다. 일반 사용자 권한으로 실행하며 외부에서 접근할 서버 포트를 열지 않는다. 인증서 오류나 사이트 접근 확인을 무시하는 옵션은 쓰지 않는다.

사이트마다 전용 브라우저 프로필을 사용하고, 직접 로그인한 창과 후속 자동 작업이 같은 프로필을 사용한다. 사용자의 평소 Chrome·Edge 프로필과 섞지 않는다. 사이트의 로그인 화면을 열었다는 사실을 로그인 성공으로 기록하지 않는다. preview.6.1부터 Windows DPAPI로 아이디·비밀번호를 암호화 저장한다. 별도 임시 프로필에서 원래 로그인 처리기로 검증한 계정만 저장하고, 계정별 자동 복구 동의·시도 전 기록·횟수 제한·실제 로그인 근거를 요구한다. Windows 보호 저장소를 쓸 수 없으면 평문으로 대체하지 않는다. Linux 합성 검사는 Windows DPAPI·실제 계정 검증을 대체하지 않는다.

비밀번호 변경·회원정보 보완·추가 인증은 사용자가 사이트에서 직접 처리한다. 여러 기기 접속으로 다른 기기의 로그인이 풀리는지 여부는 사이트별로 검증하며, 기기 간 실행을 강제로 조정하는 기능은 만들지 않는다.

## 기능 이식 원칙

강의 날짜·시각·제목을 같은 강의의 근거로 연결하고, 다른 날짜 강의를 오늘 목록에 섞지 않는다. 정상적인 빈 목록, 로그인 필요, 읽기 실패, 추가 목록 미확인을 구분한다. 실패한 새 조회로 기존의 유효한 목록·예약·시도 기록을 지우지 않는다.

출석·퀴즈·포인트는 사이트의 원래 화면과 관찰한 동작을 사용한다. 추측한 수령 API, 서버 시계·시청시간 조작, 보안 화면 우회는 추가하지 않는다. 기기 간 중복 방지는 제외해도 이 프로그램 안의 중복 클릭·횟수 제한·결과 불확실 재전송 방지는 유지한다.

| 기능 | 최종 이식 목표와 유지할 조건 |
| --- | --- |
| 강의 조회 | 기존 9개 강의 사이트를 순차 이식. PC 화면의 날짜·빈 목록·페이지 이동을 검증한다. |
| 출석·캡슐 | 닥터빌·키메디·한미·닥플의 기존 처리 순서와 완료 근거를 유지한다. |
| 닥터빌 퀴즈 | 오늘 강의 조회와 연결한 하루 1회 자동 시도. 기존 제출 횟수·불확실 잠금·실제 결과 근거를 유지한다. |
| 인터엠디 퀴즈 | 현재 제공되는 참여 상태 확인 범위를 옮긴다. 자동 정답 제출로 확대하지 않는다. |

| 종근당 | 첫 강의 확인 때 하루 한 번 새 로그인하는 기존 요구를 유지하되, PC 로그인 복구를 검증한 후 연결한다. |

| 오전 자동 실행 | 사용자가 켠 경우에만 기존 오전 8:10 실행과 유효기한을 이식한다. |
| 닥터빌 설문 | 기존 선택 기능으로 별도 검증한다. 다른 자동 기능을 추가했다는 이유로 켜지 않는다. |

모든 항목은 최종 목표다. 첫 기반 구현에서 자동 실행 기능을 완료한 것으로 표시하지 않는다. Android에서 원인이 남아 있는 한미 입장 대상 판별·메디게이트 클릭·인터엠디 로그인·브랜드관 배너 문제는 PC에서도 실제 근거로 검증한다.

## 예약과 중단

일정은 한국 시간 기준으로 PC에서 계산하고, 정시 작업은 미리 준비한다. 서버의 정시 신호를 기다리는 방식은 사용하지 않는다. 설정과 제출 시도는 외부 동작 전에 저장한다. 저장 실패 때 외부 동작을 시작하지 않는다.

전체 중지는 다음 동작과 예약 실행을 막는다. 이미 사이트에 보낸 요청을 되돌렸다고 표시하지 않는다. 실행 후 프로그램이 종료되거나 응답이 끊기면 결과를 미확인으로 보존하고 자동 재제출하지 않는다. 재시작·업데이트·새로고침으로 시도 기록을 초기화하지 않는다.

전원 꺼짐·절전·프로그램 종료로 놓친 작업은 작업별 기한을 확인한다. 기한을 지난 선착순 작업은 종료한다. 가능한 당일 입장은 해당 기능의 명시적인 정책으로 현재 기회를 확인한다. D26의 닥터빌 미입장 복구는 현재 입장 가능·미종료 근거와 기존 미시도/미소비 조건을 요구한다.

## 상주 자원과 수동 사용

대기 중에는 예약 타이머만 유지하고 사이트를 계속 새로 조회하지 않는다. 자동 작업은 동시 실행 수를 제한하고 필요한 브라우저 창을 작업이 끝나면 정리한다. 실제 Windows에서 대기·조회·영상 페이지별 메모리와 CPU 사용을 확인한다.

사용자가 직접 로그인하거나 사이트 창을 조작하고 있을 때 자동 작업이 같은 창을 이동시키지 않는다. 자동 입장 우선순위와 기존 작업의 양보를 이식하되, 사용자의 수동 로그인 화면을 강제로 닫지 않는다. 이 프로그램이 연 창만 관리하며 평소 사용하는 Chrome·Edge 창을 조작하지 않는다.

## 결과와 진단

요청 접수, 버튼 클릭, 영상 페이지 진입, 실제 재생 확인, 출석·적립 완료를 구분한다. 클릭만으로 성공 처리하지 않는다. 미제공·미신청·종료·로그인 필요·연결 실패·대상 미확인·클릭 뒤 결과 미확인을 분리한다.

일반 진단에는 PC판 버전, 고정 단계·오류 코드, 날짜·시각, 필요한 개수만 남긴다. 계정·비밀번호·쿠키·토큰·전체 URL·화면 HTML·사이트 응답 원문을 자동 저장하거나 전송하지 않는다. 사용자가 직접 파일을 내보내는 방식으로 지원한다.

## 개발과 배포 기준

기반 → 강의 조회 → 출석·퀴즈 → 자동 입장 → 자정 작업 순서로 진행한다. 읽기 전용 검증을 통과한 뒤 실제 제출 기능을 연결한다. 재구성 화면 검사와 실제 Windows·로그인된 사이트 검증을 구분한다.

Windows에서 실행, 트레이 복원, 명시적 종료, 프로필 유지, 전체 중지, 재시작 중복 방지를 확인한 뒤 사용자용 실행파일로 배포한다. 초기에는 수동 업데이트를 사용한다. 배포물에는 설치파일·사용 안내·변경 내역·체크섬만 넣고 소스·계정·개인 보고서·Android 서명 자료는 넣지 않는다. Windows에서 확인되지 않은 기능을 지원 완료라고 쓰지 않는다.

2026년 10월 26일 사용자가 별도로 공개를 요청하여 0.1.0-preview.3 배포용은 현재 구현 범위와 Windows 미검증 상태를 명시한 공개 검증판으로 게시했다. GitHub prerelease로 표시하고 Android 최신 릴리스를 유지한다. 개발자용은 공개하지 않는다. 이 게시가 실제 Windows·사이트 계정 검증 완료를 뜻하지는 않는다.

사용자의 작은 패치 요청에 따라 첫 설치용 전체 묶음과 앱 폴더 교체용 패치를 함께 제공한다. 패치는 같은 에디션의 정확한 이전 버전을 대상으로 하며 Electron 버전과 모든 실행 환경 파일 해시가 같은 경우에만 생성한다. resources/app 전체 교체와 백업으로 삭제된 모듈이 남지 않게 한다. 로그인·설정 저장소는 변경하지 않는다. 실행 환경이 달라지는 업데이트는 전체 묶음으로 전달한다. 자동 다운로드·실행 기능은 별도 구현 전까지 추가하지 않는다.
