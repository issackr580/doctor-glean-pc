# PC 오류 재현과 검증

PC-010의 목적은 보고서 접수마다 추정 수정과 배포를 반복하는 일을 줄이는 것이다. 보고 접수·원인 분류·합성 재현·개발자 검증·배포를 구분한다. 모바일에서 참고한 설계와 Windows의 실제 동작은 별도 근거다. 개인 전달 자료나 원본 보고서를 공개 소스에 복사하지 않는다.

## 회차를 따라 확인

개발자용에서 기존 7일 진단을 켜고 문제를 한 번 관찰한다. 개발자 진단의 **입장 회차별 경과·보고**에서 사이트·날짜·시각·슬롯과 입장/준비/사전 검사 종류를 선택한다. 미리보기의 설명과 고정 필드를 확인하고 같은 내용을 TXT로 저장하거나 복사한다. 선택 보고에는 다른 회차·전체 현재 상태·내부 예약 대응 키가 없다. 파일과 클립보드에 만든 사본은 앱의 진단 삭제로 회수할 수 없다.

`pc_entry_observations_v1`은 PC 전용 관찰 계약이다. Android 알람·API·WebView 필드나 모바일 버전 형식을 덧붙이지 않는다. 임의 UUID는 진단 회차이고 기기/계정 ID가 아니다. 같은 예약 슬롯의 실제 작업 시작은 attemptIndex로 구분하며, 사전 검사와 준비는 입장 실행과 별도 회차다. 시작 당시 앱·Electron·Chromium·유효 소스 commit만 기록한다. 이전 예약을 읽었다는 이유로 알람 수신·과거 시작·버전을 만들어 넣지 않는다.

| 기록 | 해석 |
|---|---|
| reservation_observed | 현재 예약을 관찰함. OS 알람 예약/수신은 아님 |
| work_started / page_started / page_finished | 실제 작업/현재 소유 창의 콜백. 로그인 성공은 별도 |
| inspect | 고정 판독 사유·개수·boolean. 요청 실행 권한은 아님 |
| click_requested | 필수 영속 시도 소비 뒤 원래 처리기를 호출하려 함 |
| click_response | 로컬 스크립트 응답. DOM 클릭·서버 승인 전체를 증명하지 않음 |
| navigation_observed | 허용 문서로 이동함. 정확한 플레이어 도착·적립 증거는 아님 |
| playback_observed | 기존 한미 관측. 실제 출석/시청시간 인정은 별도 |
| state_observed:manual_clicked | 직접 입장 표시. 실제 도착 성공으로 바꾸지 않음 |
| work_finished 누락 | 결과 미기록. OS 종료라는 단일 원인으로 확정하지 않음 |

실제 이벤트 시각과 작업 중 performance.now 경과를 나눈다. 반복 판독은 의미가 같으면 기록/시각을 갱신하지 않는다. 새로운 작업 시작의 결론에 이전 재시도 결과를 이어 붙이지 않는다. 보관 한도로 시작이 빠졌어도 attemptIndex가 다른 경과는 현재 결과에 섞지 않는다.

기존 진단 파일·7일 opt-in·한국 날짜별 하루2000개·파일4MiB 한도를 공유한다. 회차 내보내기는 최근64회차·회차48event·compact JSON256KiB 이내이며 생략 수를 표시한다. 문자열 Boolean/숫자는 변환하지 않고 버리며 미지 상태/사유는 unknown이다. 원문·계정·쿠키·토큰·URL·절대 경로·안정적 기기 ID는 수집하지 않는다.

진단은 best effort이고 작업을 허가하는 저장과 분리된다. 진단 실패·삭제·동의 철회로 계정/예약/시도 파일을 변경하지 않는다. 철회는 기록을 비우고 진행 중 진단 lease·미리보기 token을 무효화한다. 다시 켜도 옛 콜백이 새 기록을 되살리지 않는다. 미리보기는5분간 고정하며 저장 대화상자가 열린 동안 철회했으면 쓰지 않는다. 배포용에는 이 기록기·추가 IPC·화면·모듈이 없다.

## 재현과 완료 판정

```sh
npm ci
npm run verify:pc
```

Linux 컨테이너에만 필요한 경우 `DOCTOR_GLEAN_XVFB_PATH`를 지정하고 `npm run verify:pc -- --container-no-sandbox`를 사용한다. 제품 설정은 변경하지 않는다. Node24/npm11·고정 Electron45를 유지한다.

공통 명령은 전체 Node, 구문, 실제 Electron의 catalog/automation/credentials/entry/replay/registration을 순서대로 실행한다. TAP의 실패/취소/skip/todo와 실제 통과 개수, Electron의 완료 marker를 확인한다. 현재 소스 전체 inventory와 환경의 시작/종료 SHA가 같아야 complete다. 검증 시작 즉시 이전의 현재 요약을 미완료로 바꾸며 이전 JSON만으로 통과시키지 않는다. 실패 로그·입력/출력 SHA·회차별 결과는 ignore된 verification/runs 아래에 남긴다. 이 첫 구현은 오래된 보고를 자동 재사용하지 않는다.

`complete`는 **PC 소스와 합성 환경 검사**의 완료다. Windows 묶음 실행·DPAPI·인증 사이트·다운로드 자산 검증을 대신하지 않아 releaseReady는 false다. 패키지/업데이트/게시 기준은 기존 RELEASE_PROCESS를 따른다. 검사 후 소스가 바뀌면 이전 입력 SHA의 결과이며 변경된 입력의 전체 완료로 사용하지 않는다.

replay는 새로 작성한 PC 합성17종을360/1240 폭에서 실행한다. 후보 중복·복수 버튼·신청 상태·숨긴 복제·다른 시각·다른 제목·로그인·모달·비활성·로딩·외부 행동·기한·다른 origin·클릭 직전 변경·한 번 실행을 확인한다. 네트워크는 합성 HTTPS 응답으로 대체한다. PC의 신청 충돌은 기존 not_registered 중단을 유지하며 모바일 사유를 맞추려고 제품 판정을 바꾸지 않는다. 이 재현을 특정 사용자의 원인 확정이나 실제 사이트 복구로 확대하지 않는다.

## 업데이트와 배포

사용자가 **PC 업데이트 확인**을 눌렀을 때만 고정 PC 저장소의 공개 메타데이터를 GET한다. Windows x64·distribution·현재 stable/preview 채널·공개 상태·정확한 태그/첨부 이름·업로드 상태·양의 크기·SHA-256·정확한 출처를 대조한다. preview 앱은 공개 prerelease인 PC 검증판 채널을 명시적으로 사용한다. 모바일의 stable-only 규칙을 그대로 가져오면 기존 PC 검증판을 찾을 수 없으므로 구분했다. APK·개발자용·다른 출처·불완전 자료는 후보가 아니다.

최대3페이지·페이지30건·각1MiB·전체15초이며 페이지 실패/범위 미완료/유효 자료 없음은 unknown이다. 이 확인은 메타데이터 선별이고 설치 파일 다운로드·서명·Windows 실행 검증이 아니다. 새 버전이 확인돼도 사용자가 공식 페이지를 여는 동작만 제공한다. 개발자용은 공개 업데이트를 조회하지 않고 기존 협업자 전용 Releases/Draft 안내를 사용한다. 자동 설치·원격 코드 교체·진단 업로드·서버는 추가하지 않는다.

한 보고서마다 제품 배포하지 않는다. 같은 원인의 보고를 모아 실패 재현과 수정 근거를 먼저 확보하고 개발자용에서 확인한다. 중복 제출·자료 손실·앱 시작 불가 등은 긴급 배포 대상으로 분리한다. 일반 수정은 관련 검증이 완료된 소스 기준으로 묶어 배포한다. 이전 실행물·태그·자산은 교체하지 않는다.
