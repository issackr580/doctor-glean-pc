# PC 예약과 실제 동작 검증

모바일을 함께 사용해도 PC가 무엇을 시도했는지는 로컬 기록으로 확인할 수 있다. 같은 계정의 출석·포인트 완료 상태만으로 어느 기기에서 완료했는지는 알 수 없다. PC판과 모바일판의 기록·쿠키·실행 잠금은 동기화하지 않는다.

## 화면에서 구분할 근거

| 단계 | 확인한 것 | 아직 확인하지 않은 것 |
|---|---|---|
| 예약됨 | PC에 해당 날짜·강의의 실행 예정 기록이 있음 | 로그인·정시 실행·입장 성공 |
| 사전 검사 | 현재 페이지의 같은 날짜·시작 시각·제목과 입장 버튼 판독 | 실제 클릭·미래의 버튼 상태·적립 |
| PC 클릭 확인 | PC의 입장 처리기 실행과 응답 | 사이트가 실제 입장·출석을 인정했는지 |
| 강의창 이동 확인 | 클릭 뒤 허용된 새 문서로 이동 | 대상 플레이어의 영상 진행·시청시간 |
| 영상 진행 관찰 | 읽을 수 있는 영상의 시간 진행 | 충분한 시청시간·사이트 출석·포인트 |
| 사이트 완료 상태 확인 | 사이트의 현재 완료 표시 | PC 또는 모바일 중 어느 기기가 기여했는지 |

`기존 완료 상태 확인 · PC 새 제출 없음`은 PC가 완료된 상태를 읽었다는 뜻이다. `PC 시도 이력 있음`은 같은 날 과거 시도가 있음을 뜻하며 현재 버전이 새로 제출했다는 뜻이 아니다. 예전 기록에 실행 버전이 없으면 현재 앱 버전을 소급해서 붙이지 않는다.

출석·퀴즈의 **상태만 확인**은 이전 완료도 현재 페이지에서 다시 읽는다. 저장 계정 복구나 수령/정답 제출을 하지 않는다. 자동 기능이 켜져 있어도 이번 실행이 읽기 전용이면 제출하지 않으며 화면과 JSON의 `daily.readOnly`로 구분한다.

입장의 ledger `unknown`은 재전송 방지 잠금이다. UI의 클릭·이동 근거와 함께 읽으며 단독으로 실패 또는 적립 성공으로 해석하지 않는다. 개발자 이력은 선택 동의가 켜진 뒤의 기록만 포함한다.

## 제출 없는 사전 검사

각 예약의 **사전 검사 · 클릭 없음**을 누른다. 저장된 예약의 사이트만 읽으며 임의 주소를 입력받지 않는다. 기존 작업 프로필을 사용하지만 저장 계정을 읽거나 로그인 POST를 보내지 않는다. 수동 창·다른 작업이 진행 중이면 양보하고, 정시 입장·닥터라운지가 시작되면 사전 검사를 중단한다.

검사 결과는 별도 `preflight`에 남는다. 예약 상태·예정 시각·시도 횟수·제출 잠금은 바꾸지 않는다. 미래의 버튼 부재는 대기일 수 있으며 실제 실행 시점에 다시 판독한다. 로그인 필요·대상 모호·보안 확인은 직접 확인한다. 검사가 완료돼도 실제 입장·재생·적립 성공으로 표시하지 않는다.

자동 입장 사이트를 켰더라도 그 사이트의 오늘 강의가 조회되지 않으면 새 예약이 생기지 않는다. 강의 조회 선택, 날짜·사이트별 조회 결과, 사전 신청 상태를 확인한다. 한미는 신청 상태가 확인된 강의만 기존 규칙에 따라 예약한다.

preview.14 사전 검사는 페이지 로드 직후 끝내지 않고 최대8초 동안 읽으며 안정된 대상·버튼을 확인한다. 로그인/제공자 화면은 대상 부재와 나누고 문서 교체를 기다린다. 일괄 검사의 버튼 확인·시작 전 대기·로그인 필요·확인 필요 수를 본다. 개별 결과의 판독 횟수도 남긴다. 한미 보완 입장과 블루팜 기간 판독의 합성 검증은 실제 Windows 정시 입장·적립 성공을 대신하지 않는다.

## 여러 예약과 실패한 사이트 확인

preview.13의 **예정 예약 일괄 사전 검사 · 클릭 없음**은 오늘의 선택된 입장 사이트에서 아직 시작하지 않은 예약만 순서대로 읽는다. 최대40건·2분이며 정시 작업, 전체 중지·절전·종료에 양보한다. 처리/건너뜀 수와 예약별 결과를 확인한다. 검사 중 로그인 필요는 자동 계정 제출로 바꾸지 않는다.

**이번 프로그램 실행 후 PC 클릭 / 시작 전 기록**은 프로세스 시작 시각과 각 영속 결과 시각을 비교한다. 이전 기록은 삭제하지 않으며 현재 버전이 실행한 것으로 표시하지 않는다. 결과 시각이 없는 기록은 별도 미기록으로 남긴다. 배포용에도 기본 결과 구분은 제공하고 개발자 상세 이력은 제외한다.

조회는 **이 사이트만 조회**로 다른 사이트·선택 목록을 바꾸지 않고 다시 확인한다. 로그인 필요인 저장 계정은 **저장 계정으로 로그인**으로 사용자가 직접 한 번 복구를 요청할 수 있다. 최근/당일 제한·거절 잠금은 유지하며 인증 확인 뒤 그 사이트만 다시 조회한다. 실패한 자동 로그인을 몰래 재개하거나 이전 시도를 초기화하지 않는다.

`현재 목록만 확인`은 읽은 카드의 제목·날짜·시각이 맞다는 뜻이다. 미조회 페이지와 전체 공개 강의의 완전성을 뜻하지 않는다. `목록·날짜 확인`은 해당 결과의 목록 끝·선택일 범위·편성표 대조 근거다. 달력 로딩과 추가 목록이 미확정이면 기존 강의를 남기고 저장된 목록임을 표시한다.

## 모바일을 병행하는 재확인

1. 강의 하나를 정하고 그 강의의 모바일 자동 입장만 잠시 끈다. PC를 켜고 절전되지 않는 상태에서 해당 사이트를 조회하고 예약·실행 예정 시각을 확인한다. 사전 신청은 사이트의 정상 절차를 따른다.
2. 개발자용은 **7일 진단 켜기**를 한 뒤 사전 검사를 실행한다. 정시에는 수동 사이트 창을 조작하지 않는다. 실행 직전·직후 진단 JSON을 저장하고 예정 시각·실제 시작·슬롯·PC 클릭·이동·영상 관찰을 대조한다.
3. 출석·적립은 사이트의 정상 내역에서 별도로 확인한다. 불확실하면 자동 재제출하지 않는다. 직접 처리로 전환할 때는 해당 PC 예약을 취소하고 사이트 상태부터 확인한다. 기존 계정·시도 파일을 삭제하지 않는다.

개발자 JSON에는 현재 오류보고 정보도 포함된다. 비밀번호·쿠키·정답·사이트 원문 없이 시각·사이트·기대한 동작과 파일을 공유한다. 한 기기씩 강의 단위로 검증하면 다른 강의의 모바일 사용까지 중단할 필요는 없다.

## 한계와 안전 조건

지속 백그라운드 재생과 충분한 시청시간 보장은 구현 범위에 추가하지 않았다. 다른 출처의 플레이어를 읽을 수 없으면 관찰 불가로 표시하며 원격 창 보안·TLS·동일 출처 정책을 낮추지 않는다. 실패한 계정 후보·미신청·보안 확인·날짜/대상 모호성은 우회하지 않는다. Linux 합성 검사는 실제 Windows·로그인 계정 검증과 구분한다.
