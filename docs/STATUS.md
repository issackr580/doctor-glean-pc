## v12 게시 — 예약 검증과 PC 실행 근거

현재 실행판은 **0.1.0-preview.12**다. 예약 생성·PC 입장 시도·화면 이동·영상 관찰·사이트 완료를 구분하는 표시와 읽기 전용 사전 검사, 자동 작업의 개발자 이력, PC 전용 입장 보완 판독을 추가했다. 배포용 공개와 개발자 Draft 유지를 확인했다. [v12 기록](releases/0.1.0-preview.12.md)과 [PC 검증 방법](ENTRY_VALIDATION.md)을 따른다.

## v11 디톡스 재보고와 수정

v10 Windows 재보고의 디톡스 조회는 `network_error/load_failed`로 로그인 판독 전에 중단됐고 이번 디톡스 저장 계정 복구 결과는 없었다. v11은 고정 목록의 일반 로드 실패에만 원래 고정 로그인 GET을 한 번 읽어 기존 동의·시도 제한 안에서 한 번 복구하고 조회를 다시 연다. 인증서·DNS·오프라인·시간초과·취소·변형 URL은 대체 진입하지 않으며 보안 확인·로그인 GET 재실패·복구 뒤 지속 실패는 중단한다. [v11 기록](releases/0.1.0-preview.11.md)을 따른다.

Node144·구문 검사, Linux Electron 합성 HTTPS 관리 창60·자동 작업28·계정90, 최종 Windows 묶음 관리 창60/55와 에디션 저장소 분리·소스137파일 재현·동일 runtime 패치를 확인했다. 수동 runner 업로드 뒤 모든 ZIP 내부 파일이 로컬 검증본과 일치했다. 배포용 공개·개발자 Draft 유지·이전 자산 불변을 확인하고 일회성 업로드 작업을 제거했다. 이후 v11 Windows 재보고에서 디톡스 복구·새 목록 조회를 관찰했다. 다른 사이트와 조건으로 확대하지 않는다.

## v10 수정과 Windows 재보고

- 사용자는 당일 출석·퀴즈를 모바일에서 먼저 처리했다고 확인했다. PC 진단은 출석4곳과 닥터빌 퀴즈를 완료로 읽었지만 모두 새 제출은 없었다. 완료 판독을 PC의 신규 자동 제출·적립 성공으로 기록하지 않는다.
- 닥터빌 자동 퀴즈 경로는 `product_link_ambiguous`로 제출 전에 중단됐다. 후속 상태 확인의 완료 판독과 별도 결과다. 잘못된 제품을 고르지 않도록 대상 모호성 중단을 유지하며, 미참여일의 실제 자동 제출은 남은 확인이다.
- 사용자는 키메디·후다닥·닥플 플러스에서 직접 로그인해야 했다고 보고했다. 키메디 복구는 제출 후 홈에서 인증 근거를 확인하지 못해 `time_limit`, 후다닥은 차단된 이동1회 뒤 `login_required`였다. 닥플은 앞선 복구가 인증으로 판독된 뒤 후속 요청이 `cooldown`이며, 수동 로그인 뒤 출석 완료가 관찰됐다. 이 기록만으로 세션 상실·후다닥의 정확한 차단 목적지를 단정하지 않는다.
- 키메디의 확정 원인은 PC runner가 저장 계정 복구에도 `validation:false`를 보내 원본 background proof의 입력 검사를 통과하지 못한 연결 오류다. v10은 후보 검증에만 validation 필드를 보내고 복구에는 원래 background 옵션만 보낸다. vendor·인증 근거·허용 경로·재제출 제한은 변경하지 않는다.
- 후속 v10 수정은 후다닥의 고정 PC 목록 로드 실패 때 원래 로그인 GET을1회 읽고, 실제 인증 POST 응답·제출 ACK 뒤 목적지 이동이 차단되면 허용 범위를 늘리지 않고 고정 PC 페이지를1회 다시 읽는다. 비밀번호 거절·보안 확인은 넘기지 않으며 목적지나 HTTP200만으로 인증하지 않는다.
- 닥플은 작업 페이지의 기존 출석 calendar GET으로 현재 서버 세션을 확인한 뒤 로그인 복구 필요 여부를 정한다. 일시적인 로그아웃 표시만으로 작업 창을 닫지 않으며 고정 보호 페이지·정상 calendar 응답이 필요하다. 한 작업의 읽기는1회이고 토큰·문서·날짜가 바뀌면 이전 증거를 무효화한다. 복구 성공 뒤 해당 프로필 저장을 마치고 창을 닫는다. 재시도 제한과 이전 시도 기록은 유지한다.
- 닥터빌 자동 퀴즈는 제품 탐색 전에 날짜가 맞는 기존 참여 완료/오답 상태를 읽는다. 미참여 때는 PC 중복 링크 보완 판독으로 같은 관찰된 제품 URL의 fragment·표준 추적 인자 차이를 구분한다. 날짜·제품명·제품 식별이 하나로 모일 때만 실제 링크를 사용한다. 서로 다른 제품·알 수 없는 인자의 차이는 합치지 않고 기존1회 제출 기록·완료 근거를 유지한다.
- 한국 시각 자정 닥터라운지는 `mission_changed`, 제출 마스크0으로 중단됐다. 모바일 v114의 PC 미이식 상태를 유지하며 이 로그인 수정에 섞지 않는다.
- 검증 결과·게시·Windows 재확인 범위는 [v10 기록](releases/0.1.0-preview.10.md)을 따른다. 과거 공개 릴리스·개발자 Draft·기존 자산은 유지한다.

## 이번 수정

v8 Windows 재보고에서 닥터빌 저장 성공과 기존 작업 프로필 인증을 확인해9사이트가 저장됐다. 디톡스는 실제 POST1회·HTTP302 뒤 메인 화면과 보호 목록까지 이동했으나 눈에 보이는 로그아웃을 못 찾아 약46.6초 시간 초과였다. 사용자는 사이트 열기 실패 뒤 고정 로그인 화면에서는 직접 로그인할 수 있고, 로그아웃은 상단 프로필을 열어야 보인다고 확인했다.

공개 CSS의 `#header .top_wrap .content_wrap .my_box`는 기본 display:none이고 `.active`에서 열린다. v9은 그 안의 정확한 `.link_wrap a.logout`과 안전한 원래 로그아웃 목적지/함수 참조를 읽기만 한다. 후보 검증에는 네이티브 실제 인증 요청/정상 응답·제출 ACK·1회 보호 목록 재확인·로그인/비밀번호 충돌 없음도 모두 요구한다. 숨겨진 링크 하나·302·주소만으로 저장하지 않으며 메뉴·로그아웃을 클릭하지 않는다. 이미 인증된 작업 프로필은 비밀번호를 다시 읽거나 제출하지 않는다.

수동 사이트 열기의 고정 목록 GET이 실패하면 검증된 고정 로그인 GET을 한 번 연다. 로그인도 실패하면 기존 오류/재시도 창을 유지한다. TLS·원격 창 격리·사이트/에디션별 프로필·계정과 시도 이력을 변경하지 않는다.
