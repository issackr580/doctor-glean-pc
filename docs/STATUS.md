# PC판 현재 상태와 다음 작업

## PC-011 — 명시적 수강 신청 (preview.22 작업)

아직 입장 시도를 소비하지 않은 예약에 신청하기를 연결하고, 한미 미신청 강의는 조회 목록에서도 신청할 수 있게 한다. 관리 창이 보낸 임의 URL/제목이 아니라 저장된 예약 또는 제목·날짜·시작시각에 묶인 조회 키를 사용한다. 원래 사이트를 표시하고 새 문서의 같은 강의·단일 신청 버튼을 확인한 뒤 사용자 요청당1회만 실행한다. 이미 신청 완료면 읽기만 하며 중복/개인 입력/동의/결제/보안 확인은 사이트에서 직접 마친다.

새 registration-attempts-v1.json에 제출 전에 독립 기록한다. 입장/로그인/기존 v1 기록·슬롯은 변경하지 않는다. 재시작·미확인 뒤 같은 신청은 재제출하지 않고 상태만 읽는다. 신청 클릭과 완료를 구분하며 실제 완료 표시를 확인한 뒤 사용자가 신청 창을 마치면 목록을 다시 읽고, 설정·원래 기한·미소비 조건에 맞는 예약만 다시 준비한다. 취소/이미 입장 시도한 예약은 되살리지 않는다. 실제 Windows/인증 사이트 신청은 별도 확인이다.

기준 공개 빌드: **0.1.0-preview.21**, 2026-10-29. 실행 소스 `3687d014c5f6482c322d9b7ab502ef58c73a8d61` / `pc-source-v0.1.0-preview.21`. 배포용은 공개 prerelease, 개발자용(ID427335872)은 지정 collaborator 전용 Draft다. 전체 ZIP·20→21 패치·소스 ZIP을 재다운로드해 서버 SHA·체크섬·검증본 내부 파일 전체를 대조했고 독립 웹의 공개/404 경계를 확인했다. 개인 보고·전달 자료·실사용 활동은 공개 기록에 포함하지 않는다.

## PC-010 — 회차 진단·재현·검증 체계 게시

기존7일 개발자 opt-in·하루2000개·파일4MiB 안에서 입장/준비/사전 검사 회차의 실제 콜백·고정 개수/사유·단조 경과를 연결한다. 시작 당시 버전만 기록하며 선택한 회차만 미리본 동일 내용으로 저장/복사한다. 철회/삭제는 새 회차 진단 lease·미리보기 token을 무효화하며 계정/예약/필수 시도 저장과 독립적이다. 클릭·허용 문서 이동을 정확한 플레이어 도착·출석/적립 성공으로 확대하지 않는다. 원래 사이트 행동·기한·한미5슬롯·v1 저장 형식·vendor v113을 유지한다.

고정 입력의 verify:pc는 Node223·구문·실제 Linux Electron45/Xvfb 합성 HTTPS 관리94·자동30·계정121·입장66·replay136(34시나리오)을 통과했다. 검사 중 소스 변경의 미완료 처리도 확인했다. 빌드된 Windows 묶음은 Linux Electron 관리 창 개발자94/배포80·같은 상위 appData의 에디션 분리·새 모듈 포함/제외를 확인했다. 깨끗한 소스166파일에서 의존성·Node223·구문을 재현하고20→21 동일 runtime 패치를 확인했다. 실제 Windows 실행·DPAPI·실계정 로그인/입장/영상/적립은 별도 재확인이다.

PC 업데이트 확인은 누를 때만 고정 PC 공개 메타데이터의 Windows x64·배포용·현재 stable/preview 채널과 정확한 첨부/출처를 대조해 공식 페이지를 연다. 개발자용은 공개 조회 없이 협업자 Draft 안내다. 실패·부분 조회·유효 자료 없음은 최신 판정이 아니다. 자동 설치·원격 코드/규칙·진단 전송·서버는 없다. [품질 흐름](QUALITY_WORKFLOW.md)을 따른다.

[수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40794729941)는 고정 소스·전체 파일 해시·이전 자산 SHA를 대조해 기존 Draft에만 업로드했다.12개 자산의 재다운로드 검증 뒤 배포용만 공개했다. 완료한 임시 workflow를 제거하며 과거 릴리스/자산·모바일을 변경하지 않는다. [v21 기록](releases/0.1.0-preview.21.md)에 근거를 남겼다.

## v20 게시 — 수동 로그인·한미 결과 확인·닥터빌 상세 대조

일부 사이트에 수동 로그인 주소가 빠져 메뉴에서 invalid_site 예외가 날 수 있던 연결을 보완한다. 기존 credential registry의 고정 주소만 연결하고 닫힌 창·허용되지 않은 주소의 메뉴 호출은 탐색 없이 처리한다. 허용 origin·원격 창 보안·프로필을 확대하지 않는다.

한미의 원래 loginProcess POST 정상 응답과 제출 ACK·새 문서를 확인한 경우에만 고정 보호 목록을1회 GET한다. 로그인 결과의 로그아웃/비밀번호 충돌 자체를 인증으로 삼지 않으며 새 문서의 기존 인증 근거가 필요하다. 비밀번호 변경·추가 인증·실패 응답·다른 결과 경로·반복 POST는 중단한다.

닥터빌은 목록에서 일정 대조가 불충분할 때 단일 제목 카드의 관찰된 고정 seminarId 상세 링크만1회 읽는다. 상세에서는 제목에 포함된 날짜와 끝 시각을 일정으로 쓰지 않고 새 문서의 실제 제목·날짜·첫 시작시각·원래 버튼을 엄격히 대조한다. 기존 원본이 상세로 이동한 경우도 같은 PC 판독을 사용한다. 중복 제목·위험한 링크·일정 미확정이면 클릭하지 않고, 사전 검사는 이동하지 않는다. 기존 영속 기록·기한·한미5슬롯·receipt 형식은 유지한다.

Node205·구문, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창84·자동 작업30·계정121·입장66과 기존 v19 reader 읽기/다시 저장 호환을 확인했다. 최종 Windows 묶음 개발자84/배포78·에디션 분리, 깨끗한 소스156파일 재현·19→20 동일 runtime 패치를 확인했다. 수동 runner가 검증본 해시·이전 자산 SHA를 대조해 기존 Draft에 업로드했고 모든 자산을 재다운로드해 검증한 뒤 배포용만 공개했다. 개발자 Draft·독립 웹 공개/404 경계를 확인했고 완료한 임시 workflow를 제거한다. 실제 Windows/계정의 재확인과 합성 검증을 구분하며 개인 실사용 시각·활동·원본은 공개 인계에 포함하지 않는다. [v20 기록](releases/0.1.0-preview.20.md)을 따른다.

## v19 수정과 게시

취소가 이미 완료된 상태에서도 시작한 load/evaluate의 뒤늦은 실패를 관찰한다. 원본 두 bounded 함수의 미처리 rejection 조건을 strict Node로 재현하고 공통 함수로 보완했다. 취소한 작업을 재개하거나 외부 제출을 다시 보내지 않는다. 실제 Windows 팝업의 정확한 오류명과 동일 원인은 미확정이다.

일반 보고의 runtimeFaults는 현재 프로세스 최근10개 고정 코드·알려진 PC src 파일/행/열만 메모리에 보관한다. uncaughtExceptionMonitor는 원래 Electron/Node 예외 처리·팝업·종료를 유지하며 새 자동 제출을 중지한다. 처리된 예외도 원래 오류를 전달해 저장 실패와 구분한다. 원문·stack·절대 경로·URL·계정·쿠키·토큰은 남기지 않는다.

개발자 기록기만 기존7일 opt-in·2000개/일·4MiB 한도 안에서 같은 최소 오류와 실행 버전을 보존한다. 배포용 추가 기록기·전용 IPC·자동 전송은 없다. 기존 계정·프로필·외부 시도와 수동 창을 유지한다. 직접 요청 개발자3초/배포10초, 자동60초/15분3회·사이트별 하루10회 제한은 유지한다.

Node201·구문, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창78·자동 작업30·계정103·입장54를 통과했다. Windows 묶음 관리 창 개발자78/배포72·에디션 분리·깨끗한 소스155파일 재현·18→19 동일 runtime 패치를 확인했다. [수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40644682408)는 검증본 전체 파일 해시·이전 자산 SHA를 대조해 기존 Draft에만 업로드했다. 전 자산의 다운로드 검증 뒤 배포용만 공개했고 개발자 Draft·독립 웹 공개/404 경계를 확인했다. 완료한 임시 workflow를 제거하고 과거 릴리스·자산은 유지한다. [v19 기록](releases/0.1.0-preview.19.md)을 따른다.

## preview.22 수동 Draft 업로드 준비

관리자의 게시 요청에 따라 고정 소스를 재현하고 기존 두 Draft에만 파일을 올리는 일회성 workflow_dispatch를 준비했다. 검증본 전체 파일 해시·기존 v21 자산을 대조하며 공개는 다운로드 검증 뒤 배포용에만 별도로 수행한다. 개발자용은 Draft다. 예약·push/PR 실행·공개 Actions artifact는 없고 완료 뒤 workflow를 제거한다.
