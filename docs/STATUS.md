## 이번 수정

preview.6.1 보고의 일부 실패는 로그인 ACK 뒤 3번째 읽기에서 blocked였다. 지연된 원래 POST와 redirect를 합성 Electron에서 재현하면 같은 증상이 발생했다. 원인은 결과 관찰 요청을 만든 뒤 로딩을 기다려 expected URL/문서 세대가 오래되는 순서였다. 이번 빌드는 로딩 후 바인딩을 캡처하고, 오래된 읽기는 새 관찰을 요구하며 비밀번호 전달은 문서가 바뀌면 실행하지 않는다. 같은 POST를 재전송하지 않는다.

허용된 인증 팝업의 동일 격리 프로필·권한 경계를 유지하고 후보 제출 뒤 확인 시간은45초로 제한한다. 범위를 벗어난 목적지는 계속 차단한다. 계정 저장과 작업 프로필 로그인을 구분하고, 자동 복구 동의가 있는 새 저장은 작업 프로필 확인 뒤 그 사이트 목록을 갱신한다. 이미 저장된 계정은 다시 입력할 필요 없이 저장 계정 로그인 또는 새 조회로 확인한다.

닥터빌3회/한미 재시도의 cooldown은 이전 실패의 결과다. 횟수는 초기화하지 않고 다음 가능 시각을 표시한다. 계정 진단에는 단계·고정 상태·허용 origin 여부·문서 세대·로그인/로그아웃 표시·차단 개수만 남긴다. 실제 사용자의 남은 실패가 모두 같은 원인인지는 업데이트 후 보고로 확인한다.

## 검증 기준점

- 이전6.1: Node112, 실제 Linux Electron 합성 HTTPS 개발자59/배포54, 자동 작업20, 계정29항목.
- 이번 최종 항목 수와 source commit은 [이번 릴리스 기록](releases/0.1.0-preview.7.md)에 적는다. 각 변경은 해당 파일과 함께 검증한다.
- Node·합성 재현·사용자 Windows 관찰을 구분한다. 코드의 `available=true` 또는 `submitted=true`만으로 복호화·서버 로그인·적립 성공을 추가 주장하지 않는다.
