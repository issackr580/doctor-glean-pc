## 이번 수정

v8 Windows 재보고에서 닥터빌 저장 성공과 기존 작업 프로필 인증을 확인해9사이트가 저장됐다. 디톡스는 실제 POST1회·HTTP302 뒤 메인 화면과 보호 목록까지 이동했으나 눈에 보이는 로그아웃을 못 찾아 약46.6초 시간 초과였다. 사용자는 사이트 열기 실패 뒤 고정 로그인 화면에서는 직접 로그인할 수 있고, 로그아웃은 상단 프로필을 열어야 보인다고 확인했다.

공개 CSS의 `#header .top_wrap .content_wrap .my_box`는 기본 display:none이고 `.active`에서 열린다. v9은 그 안의 정확한 `.link_wrap a.logout`과 안전한 원래 로그아웃 목적지/함수 참조를 읽기만 한다. 후보 검증에는 네이티브 실제 인증 요청/정상 응답·제출 ACK·1회 보호 목록 재확인·로그인/비밀번호 충돌 없음도 모두 요구한다. 숨겨진 링크 하나·302·주소만으로 저장하지 않으며 메뉴·로그아웃을 클릭하지 않는다. 이미 인증된 작업 프로필은 비밀번호를 다시 읽거나 제출하지 않는다.

수동 사이트 열기의 고정 목록 GET이 실패하면 검증된 고정 로그인 GET을 한 번 연다. 로그인도 실패하면 기존 오류/재시도 창을 유지한다. TLS·원격 창 격리·사이트/에디션별 프로필·계정과 시도 이력을 변경하지 않는다.

## 검증 기준점

- v9: Node128·구문 검사, Linux Electron 합성 HTTPS 계정50·자동 작업20항목 통과. 최종 빌드 관리 창 개발자60/배포55 통과. 별도 깨끗한 소스127파일에서 의존성 설치·Node128·구문 검사도 재현했다. 전체 ZIP·앱 패치·소스 ZIP의 파일과 기준 commit을 대조했다.
- [배포용 v9](https://github.com/issackr580/doctor-glean-pc/releases/tag/pc-v0.1.0-preview.9)은 공개했고, 개발자용 v9은 같은 PC 저장소의 지정 collaborator 전용 Draft다. 공개 전체/패치/소스 ZIP과 인증한 개발자 패치 다운로드의 SHA를 확인했다. 실행 소스는 `c1612d9e51187bc5270e4d6283af468fa5213808`이며 게시 확인 문서는 그 이후의 문서 변경이다. [게시·패치 기록](releases/0.1.0-preview.9.md)을 따른다.

- v8: Node126·구문 검사, Linux Electron 합성 HTTPS 계정41·자동 작업20항목 통과. 최종 빌드 관리 창 개발자59/배포54 통과. 배포용 v8 공개·개발자용 협업자 Draft 등록과 다운로드 SHA를 대조했다.

- 이전6.1: Node112, 실제 Linux Electron 합성 HTTPS 개발자59/배포54, 자동 작업20, 계정29항목.
- 이번7: Node119·구문 검사, Linux Electron 합성 HTTPS 관리 창 개발자59/배포54·자동 작업20·계정36항목 통과. 별도 소스 추출 뒤 npm ci --ignore-scripts와 Node119·구문 검사도 통과했다.
- 배포용 v7은 [PC 저장소 릴리스](https://github.com/issackr580/doctor-glean-pc/releases/tag/pc-v0.1.0-preview.7)에 공개했다. 전체 ZIP·작은 패치·소스 ZIP 다운로드와 SHA를 대조했다. 실행파일의 소스 기준은 [이번 기록](releases/0.1.0-preview.7.md)을 따른다.
- [개발자 진단 수집](DIAGNOSTICS.md)은 PR#1로 병합했다. 소스 기준 태그 이후의 문서 변경이며 제품 실행 코드는 바꾸지 않는다.
- Node·합성 재현·사용자 Windows 관찰을 구분한다. 코드의 `available=true` 또는 `submitted=true`만으로 복호화·서버 로그인·적립 성공을 추가 주장하지 않는다.
