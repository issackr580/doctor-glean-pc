## preview.43 — 자동입장 정리와 닥터빌 신청·닥플 출석

후다닥과 닥플의 자동입장 및 입장용 로그인 복구를 중단한다. 디톡스는 기존 중단 정책을 유지한다. 종근당은 강의 조회만 연결되어 있다. 남은 예약은 각 에디션의 기존 저장 형식으로 닫고 선택, 계정, 조회, 직접 이용, 시도·회차 기록을 보존한다.

닥터빌을 조회할 때 선택 날짜와 상관없이 원래 라이브 목록과 확인 가능한 다음 페이지에서 수강일 전 신청 가능 강의를 찾는다. 날짜·시각·제목·단일 공식 ID와 신청 표식을 확인하고, 수강 당일과 정원 마감은 알리지 않는다. 공식 ID로 중복 알림을 막고 일정의 닥터빌 사전 신청에서 해당 상세를 직접 열 수 있다. 기존 조회 작업의 시간과 페이지 한도 안에서 읽으며 새 상시 감시나 자동 신청은 없다. 명시적으로 선택한 설문 개시 확인과 마감 알림은 각 기존 한도를 따른다.

11월 28일 Windows 보고에서 닥플 출석과 계정 복구는 전송 없이 끝났고 뒤이은 조회가 사이트 대기로 기록됐다. 보고의 정보만으로 서버 제한의 종류와 최초 발생 요청을 특정할 수 없었다. 접속 제한의 상태와 기한을 오류보고에 추가하고, 열린 공식 달력의 출석 완료는 서버에 새 요청을 보내지 않고 읽는다. 로그인 주소에서 홈으로 돌아오면 공식 달력으로 기존 인증을 한 번 확인한다. 실제 사이트에서의 복구·출석·Windows 알림과 실제 전송량은 별도 확인이 남았다.

## PC-019 — 입장 상세 재확인·HTTPS 로그인·개장 후 라운지 (게시 완료)

preview.30에 반영해 게시했다. 개인 원문을 옮기지 않고 대표 실패 조건을 합성으로 재현한다. 닥터빌은 기존 상세에서 전체 제목을 못 찾을 때 원래 목록을 한 번 GET으로 다시 읽는다. 현재 목록에서 관측한 단일 상세만 사용하며 새 상세의 완전 제목·날짜·첫 시작 시각·원래 입장 버튼을 다시 확인한다. 이미 확인된 scheduleIdentity는 다른 ID로 바꾸지 않는다. 제목의 부분 일치·이미지 alt·표기 차이는 진단 개수일 뿐 입장 권한이 아니다. em/b의 완전한 보이는 제목은 기존 독립 일정 판독과 연결한다.

디톡스의 고정 공개 목록에서 HTTP 로그인 리디렉션을 별도로 관측했다. HTTP 이동은 차단하고 반환 query를 버린 뒤 기존 고정 HTTPS 로그인 GET만 페이지당 한 번 허용한다. 최초 목록 GET에 한정하며 자격 네트워크 관찰/입장 dispatch 뒤에는 대체하지 않는다. 기존 저장 계정 동의·quota·검증 wrapper를 유지하고 복구 후 원래 목록으로 돌아간다. 그 밖의 차단은 network 재시도가 아닌 blocked/policy_rejected로 구분한다.

키메디 라운지의 개장 전 완료 표시로 당일 작업을 확정하지 않는다. 00:01:03 이후 시작한 새 GET의 완료/미완료만 사용하며 실제 클릭 전 필수 batch 저장과 소비 기록은 유지한다. 개발자 입장 상세 기록은 기존 6사이트에서 현재 지원 9사이트로 보완하고 제목 실패 개수·차단 주소 종류·연결 오류 종류만 남긴다. 원문 제목/주소/query/계정은 추가하지 않는다. 메디게이트의 ID/상태가 불완전하거나 서로 다른 중복 후보는 임의로 합치지 않는다.

Node326·구문·Linux Electron 입장314개를 확인했다. 전체 고정 입력 검사·Windows 묶음·깨끗한 소스·서버 자산/서명 피드 결과는 게시 인계에서 구분한다. 현재 실제 Windows·회원 상세 제목/DOM·로그인/입장/재생/적립 성공은 이 변경으로 확인하지 않았다. 모바일/vendor·계정/설정·예약/필수 시도·runtime·updater/helper는 보존한다.

## 닥플 읽기 전용 HTTP 확대

닥플의 현재 월 출석 달력은 기존 PC 프로필의 토큰과 고정 HTTPS GET으로 먼저 읽는다. 달력에 오늘 출석이 기록됐으면 창을 만들지 않고 완료로 표시한다. 읽기 전용 확인은 오늘 출석이 없고 기존 시도 이력도 없으면 대기 상태를 반환한다. 실제 출석이 필요한 경우 원래 화면과 영속 시도 원장을 사용한다. 불완전한 응답은 화면으로 이어가고 403·429·서버 지정 503 대기 중에는 창이나 재로그인을 열지 않는다. 계정·프로필·작업 범위가 바뀐 응답은 적용하지 않는다.

닥플 강의 조회는 자동 로그인 복구 직후 새 세션으로 기존 LIVE API를 한 번 더 읽는다. 전체 페이지와 공식 ID·일정·신청 상태가 검증되면 목록 화면을 다시 열지 않는다. 실패하면 남은 조회 시간 안에서 화면을 한 번 사용한다.

Linux Electron 45의 합성 서버 비교에서 이미 출석한 날에는 브라우저 생성 1→0, 요청 4→1, 응답 본문 6,355→62바이트였다. 로그인 복구 후 목록 조회는 브라우저 2→1, 요청 6→4, 응답 본문 13,347→6,596바이트였다. 두 비교의 POST 및 리디렉션은 0회다. 복구용 로그인 자체는 동일한 합성 콜백을 사용했다. 불명확한 출석 응답 뒤 화면이 필요했던 사례에서는 요청이 4→5회였다. 합성 문서 본문 비교이며 실제 Windows 전체 전송량과 회원 사이트 결과는 별도 확인 대상이다.

종근당과 닥플의 기존 목록 API 경로가 있다. 키메디 목록·상세는 PC 프로필의 인증 갱신과 전체 페이지 검증이 다음 확인 항목이다. 메디게이트는 회원 집계 읽기를 우선 검토하고 공개 포틀릿은 부분 자료로 취급한다. 다른 사이트는 응답이 선택일·공식 ID·신청 상태·전체 범위를 증명하는 계약을 확인한 뒤 전환한다. [사이트별 계약과 검증 경계](PORTING_DIRECTION_V156.md)

## PC 전체 데이터 검토와 메디게이트 수강 집계

[10개 사이트의 읽기 경로와 남은 계약](PC_NETWORK_PATHS.md)을 확인했다. 진행 중인 동일 사이트 조회를 합치고, 입장이 조회를 선점하면 완료된 사이트를 다시 읽지 않는다. 메디게이트는 같은 월의 원래 집계 응답과 행사 화면의 수치가 일치할 때만 입장 전후를 비교한다. 외부 강의 주소를 자동으로 허용하지 않는다. 이동이 차단돼도 수강 집계 증가를 확인하면 종료하고 불명확한 결과에 입장을 반복하지 않는다. 월별 주소를 설정할 수 있고 공식 화면의 해당 월 링크도 사용한다. 실제 Windows 회원 집계와 네트워크 사용량은 별도 확인 대상이다.
