## 변경과 검증

기존 개발자7일 opt-in·하루2000개·파일4MiB 안에서 회차 관찰을 연결하고 선택한 사이트/슬롯의 고정 보고를 미리보고 동일 내용으로 저장/복사한다. 새 회차 기록은 시작 당시 버전·실제 콜백·단조 경과·고정 타입만 포함한다. 시도 소비·클릭 응답·허용 문서 이동·영상 관측과 실제 도착/적립을 구분하고 종료 누락 원인을 추정하지 않는다. 진단 실패·삭제·철회는 필수 시도 저장과 독립적이며 옛 회차 진단 lease·미리보기 token을 차단한다. 배포용에 추가 기록기·모듈·preload/IPC·화면을 넣지 않는다.

verify:pc는 전체 Node·구문·실제 Electron 다섯 suite를 현재 입력/결과 SHA와 연결한다. Node223·구문·Linux Electron45/Xvfb 관리94·자동30·계정121·입장66·replay136(합성34시나리오)을 통과했고 입력 변경의 미완료 판정도 확인했다. 빌드된 Windows resources/app는 Linux Electron에서 개발자94/배포80과 같은 상위 appData의 에디션 분리를 확인했다. 깨끗한 소스166파일의 의존성·Node223·구문 재현·20→21 동일 runtime 패치를 확인했다. 합성 통과는 실제 Windows·DPAPI·인증 사이트 성공이 아니다.

명시적 PC 업데이트 확인은 고정 PC 저장소·Windows x64·배포용·현재 stable/preview 채널과 정확한 공개 첨부/출처를 선별해 공식 페이지를 연다. 개발자용은 기존 협업자 Draft 안내다. 실패/부분 조회는 최신이 아니다. 자동 설치·원격 규칙·진단 전송은 없다.

[수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40794729941) 뒤12개 자산을 재다운로드해 서버 SHA·체크섬·ZIP 내부 파일 전체를 검증하고 배포용만 공개했다. 개발자 Draft·독립 웹 공개/404 경계를 확인했고 완료한 임시 workflow를 제거한다. 자동 게시·예약 실행·공개 개발자 artifact는 남기지 않는다.

## 다음 작업과 경계

- 개발자용에서7일 진단 켜기→한 회차 관찰→입장 회차별 경과에서 미리보기→선택 보고 저장/복사 순서다. 진단을 켜기 전 과거 경과를 만들어 채우지 않는다. 파일/클립보드 사본은 앱에서 회수하지 못한다. [품질 흐름](QUALITY_WORKFLOW.md)과 [PC 검증](ENTRY_VALIDATION.md)을 따른다.
- Windows 실제 로그인·저장/복구·DPAPI·정시 입장·정확한 플레이어·영상/적립은 별도 확인이다. 인증 DOM이 없으면 실제 원인이나 성공을 확정하지 않는다. PC 회차 관찰과 기존 계정 trace를 구분해 읽는다.
- DPAPI·사이트/에디션별 프로필·수동 창 보호·동의·제출 전 영속 기록·기한·한미5슬롯·불확실 자동 재제출 중단을 유지한다. 직접 개발자3초/배포10초·자동60초/15분3회·하루10회와 기존 파일 형식을 유지하고 계정/시도 파일을 지우지 않는다.
- vendor v113이다. 모바일 소스·APK·서명·릴리스는 변경하지 않았고 모바일 동작/검증을 PC 성공으로 대체하지 않는다. 종근당 새 로그인·설문·지속 재생·추가 사이트 반복 입장은 별도 범위다.

같은 에디션 preview.20만20→21 패치를 사용한다. 트레이 완전 종료→resources/app 백업→패치 app 전체 교체→하단 버전 확인 순서다. X는 숨기기다. 첫 설치·다른 버전은 전체 ZIP이다. 두 에디션의 로그인·설정은 분리한다.
