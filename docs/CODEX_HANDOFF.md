## 수정과 검증

수동 로그인 주소가 빠진 사이트를 기존 credential registry의 고정 주소에 연결했다. 잘못된 주소와 닫힌 창의 늦은 메뉴 호출은 탐색 없이 처리한다. 허용 origin·원격 창 격리·프로필은 확대하지 않는다.

한미의 공개 원래 loginProcess POST를 기존 Network 개수/HTTP 상태 관찰에 포함했다. 실제 정상 인증 응답·제출 ACK·새 결과 문서·검토한 충돌 조건을 모두 만족할 때만 고정 보호 목록을1회 GET하고 그 문서의 기존 인증 근거를 요구한다. 로그아웃/비밀번호 충돌 자체를 인증으로 삼지 않는다. 비밀번호 변경·추가 인증·실패 응답·다른 결과 경로·중복 POST는 중단하며 재제출하지 않는다. route=login_result·hmpLoginResult/hmpAdditionalStep는 고정 분류/boolean이고 인증 근거가 아니다.

닥터빌은 목록 일정 대조가 불충분할 때 단일 제목 카드의 관찰된 고정 seminarId 상세 링크만1회 읽는다. 원래 엔진의 상세 이동에도 PC 판독을 적용해 새 문서의 실제 제목·날짜·첫 시작시각·원래 버튼을 엄격히 대조한 뒤 기존 영속 권한으로만 클릭한다. 제목 날짜·끝 시각·중복·위험 링크로 클릭하지 않고 사전 검사는 이동하지 않는다. 기존 read_only 이유를 사용해 안정된 receipt/시도 형식을 유지하며 실제 v19 reader의 읽기/다시 저장 호환을 확인했다.

Node205·구문, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창84·자동 작업30·계정121·입장66을 통과했다. Windows 묶음 관리 창 개발자84/배포78·같은 appData 상위 경로의 에디션 분리, 깨끗한 소스156파일 재현·19→20 동일 runtime 패치를 확인했다. [수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40670979779)는 고정 소스·검증본 전체 파일 해시·이전 자산 SHA를 대조해 기존 두 Draft에만 업로드했다. 전 자산을 재다운로드해 서버 SHA·체크섬·ZIP 내부 파일 전체를 검증한 뒤 배포용만 공개했다. 개발자 Draft·독립 웹 공개/404 경계를 확인했다. 완료한 임시 workflow를 제거하고 자동 게시·예약 실행·공개 개발자 artifact는 남기지 않는다.

## 다음 작업과 경계

- 실제 Windows의 한미 로그인·닥터빌 상세 DOM/정시 입장·영상/적립은 별도 재확인이다. 인증된 실제 DOM은 확보하지 않았고 합성 통과를 실계정 성공으로 확대하지 않는다. [PC 검증 방법](ENTRY_VALIDATION.md)을 따른다.
- v19의 최소 오류 근거와 기본 예외 처리·개발자 opt-in 기준을 유지한다. 팝업 재발 시 가능하면 완전 종료 전에 일반 오류보고를 저장한다. 사이트 자체의 모든 alert·Windows 오류를 포괄하지 않는다.
- DPAPI·격리 후보·사이트/에디션별 프로필·수동 창 보호·동의·제출 전 영속 기록·기한·한미5슬롯·불확실 자동 재제출 중단을 유지한다. 직접 제출 개발자3초/배포10초·자동60초/15분3회·사이트별 하루10회 제한과 기존 파일 형식을 유지한다. 계정·시도 파일을 지우지 않는다.
- vendor v113이며 모바일 변경을 PC에 반영된 것으로 가정하지 않는다. 모바일 소스·APK·서명·릴리스·개인 Chrome/Edge 프로필은 수정하거나 가져오지 않는다. 종근당 새 로그인·설문·지속 재생은 별도 범위다.

같은 에디션 preview.19만19→20 패치를 사용한다. 트레이 완전 종료→resources/app 백업→패치 app 전체 교체→하단 버전 확인 순서다. X는 숨기기다. 첫 설치·다른 버전은 전체 ZIP이다.
