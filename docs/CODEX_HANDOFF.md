## 변경과 검증

다음 소스 preview.25(게시 준비)는 PC-014다. 목록에서 날짜가 빠진 모든 제목 후보를 확인한 경우 기존 CatalogStore의 동일 사이트/날짜/제목/시작시각에 연결된 단일 관찰 상세를1회 GET하고 새 상세를 엄격히 검증한다. 사전 검사도 같은 읽기를 허용하는 D24를 따른다. 클릭한 현재 회차의 사전 검사 경고를 추가하지 않고 개발자 opt-in TXT에는 기존 entryJournal을 포함한다. [STATUS](STATUS.md)·[작업 기록](releases/0.1.0-preview.25.md)을 먼저 확인한다. 공개 다운로드는 아직 위 preview.24다.

닥터빌 목록에서 같은 두 열 날짜/강의 묶음과 각 강의의 제목·전용 시작시각을 함께 확인한다. 빈 날짜 열은 같은 부모에서 바로 이어지는 동일 구조 단일 카드 행에 한정한다. 전역의 마지막 날짜를 입장 근거로 쓰지 않고 숨긴/무관한 행·다른 영역·요일/날짜 오류·충돌·중복 대상을 거절한다. 6단계 조상·행당400요소/12000글자·날짜 열12요소·형제400행으로 제한하고 클릭 직전에도 다시 판독한다. 합성 배치는 실제 인증 DOM의 클래스나 원래 실패 원인 확정이 아니다.

개발자 선택 보고에 날짜 누락/오류/충돌/불일치·시작시각 오류/불일치·공유 날짜 사용의 고정 개수만 추가한다. 원문 날짜·제목·HTML은 수집하지 않으며 receipt/inspection·필수 시도 형식은 유지한다. 사전 검사 문구는 제목 후보 발견과 미발견을 구분한다. 사전 검사와 신청 상태 확인은 읽기 전용이고 원래 입장 처리기는 기존 영속 기록 이후 실행한다. 기한·취소/소비 기록·한미5슬롯·불확실 재제출0회·DPAPI·프로필·허용 사이트/IPC·수동 창 보호를 유지한다.

고정 입력 verify:pc는 Node234·구문·Linux Electron45/Xvfb 합성 HTTPS 관리105·자동30·계정121·입장110·replay136·신청193, Electron 전체695개를 통과했다. 입력/결과 SHA와 시작/종료 환경이 일치한다. 최종 Windows resources/app의 Linux Electron 관리 창 개발자105/배포91·같은 상위 appData의 에디션 분리·깨끗한 소스172파일·의존성·Node234·구문 재현을 확인했다. 작은 패치는23→24를 비교 기준으로 생성했으며 같은 에디션20/21/22/23의 실제 runtime·전체 app 교체 결과가 목표 전체 ZIP과 같은8경우를 검증했다. 중간 버전 패치를 순차 적용할 필요가 없다. 합성·파일 검증은 실제 Windows·DPAPI·인증 사이트 성공이 아니다.

[수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40842971586) 뒤12개 자산을 재다운로드해 서버 SHA·체크섬·ZIP 내부 파일 전체를 대조하고 배포용만 공개했다. 개발자 Draft·독립 웹 공개/404 경계를 확인했다. 완료한 임시 workflow를 제거하며 자동 게시·예약 실행·공개 개발자 artifact는 남기지 않는다.
