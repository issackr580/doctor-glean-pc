## 마지막 수정과 검증

v10 Windows 재보고의 디톡스 조회는 고정 목록 load_failed로 로그인 판독 전에 종료됐고 새 저장 계정 복구 결과가 없었다. v11은 이 일반 로드 실패에만 원래 고정 로그인 GET을 한 번 읽어 기존 로그인 필요 판독·동의한 저장 계정 복구·목록 재조회를 연결했다. 인증서·DNS·오프라인·시간초과·취소·임의 URL에는 대체 진입하지 않는다. 보안 확인과 기존 시도 제한을 유지하며 복구 뒤 목록이 다시 실패해도 두 번째 로그인 POST는 없다.

Node144·구문 검사, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창60·자동 작업28·계정90, 최종 Windows 묶음 관리 창 개발자60/배포55 통과. 같은 appData 상위 경로의 에디션 분리와 깨끗한 소스137파일 재현·10→11 패치의 동일 runtime을 확인했다. GitHub 수동 runner 재빌드 뒤 전체/패치/소스 ZIP의 모든 내부 파일이 로컬 검증본과 일치했다. [업로드 실행](https://github.com/issackr580/doctor-glean-pc/actions/runs/40446297112) 뒤 배포용만 별도로 공개했고 개발자용은 Draft다. 일회성 workflow·보조 스크립트는 제거했다.

Windows DPAPI·사용자 계정의 이번 디톡스 복구·편성표는 재확인 대상이다. v10의 키메디/후다닥/닥플 복구·미참여일 닥터빌 퀴즈 수정도 직접 실계정 검증 완료로 확대하지 않는다. 사용자가 모바일에서 먼저 처리한 출석·퀴즈의 완료 판독은 PC의 신규 제출 성공이 아니다. 상세는 STATUS와 releases/0.1.0-preview.11.md를 따른다.
