## 변경과 검증

PC-014는 목록에서 모든 제목 후보를 날짜 누락으로 분류할 때만 기존 CatalogStore의 같은 사이트/날짜/제목/시작시각에 연결된 단일 관찰 고정 상세 링크를 참고한다. 캐시는 입장 권한이 아니며 새 상세의 제목·독립된 날짜·첫 시작시각·원래 버튼을 다시 대조한다. 서로 다른 식별 링크·unsafe URL·리다이렉트·새 일정 불일치·클릭 직전 변경은 중단한다. 실제 DOM의 클래스나 목록 날짜 위치를 추측해 허용 범위를 넓히지 않는다.

D24는 D20의 사전 검사 읽기를 같은 상세1회 GET까지 한정해 보완한다. 계정 복구·입장/신청 클릭·팝업/재생·필수 시도 소비는 하지 않고 정시 작업에 양보한다. 현재 클릭/소비한 회차는 검사/경고를 추가하지 않으며 실제 실행 기록과 재생/적립 미확인을 유지한다. 한미 다음 슬롯은 별개로 검사한다. 기존 영속 시도·기한·취소/소비 기록·한미5슬롯·v1 저장·DPAPI·프로필·수동 창 보호·사이트/IPC 허용 범위는 유지한다.

개발자용에서 진단을 켠 동안 일반 TXT 오류보고에도 기존 entryJournal을 포함한다. 날짜 누락/시각 오류와 targetSource=catalog·catalogReference=missing/matched/ambiguous/unsafe는 고정 개수/enum이며 원문/URL/ID·계정은 없다. 기존7일 동의·64회차/48event/compact256KiB·하루2000개/4MiB·명시적 내보내기를 유지한다. 꺼짐·배포용에는 추가하지 않고 새 IPC·필수 저장 형식·자동 전송은 없다.

고정 입력 verify:pc는 Node245·구문·Linux Electron45/Xvfb 합성 HTTPS 관리106·자동30·계정121·입장142·replay136·신청193, Electron 전체728개를 통과했다. 시작/종료 소스·환경과 입력/결과 SHA가 일치한다. 최종 Windows resources/app의 Linux Electron 개발자106/배포92·같은 상위 appData의 분리·깨끗한 소스175파일·의존성·Node245·구문 재현을 확인했다. 24→25 작은 패치는 같은 에디션20/21/22/23/24의 실제 runtime·전체 app 교체가 목표 전체 ZIP과 같은10경우를 검증했다. 중간 패치는 필요하지 않다. 합성·파일 검증은 실제 Windows·DPAPI·인증 사이트 성공이 아니다.

[수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40849753664) 뒤12개 자산을 재다운로드해 서버 SHA·체크섬·ZIP 내부 파일 전체를 대조하고 배포용만 공개했다. 개발자 Draft·독립 웹 공개/404 경계를 확인했고 완료한 임시 workflow를 제거한다. 자동 게시·예약 실행·공개 개발자 artifact는 남기지 않는다. ## 다음 확인과 경계

- 실제 Windows에서 닥터빌 조회의 단일 상세 참고·새 일정 대조·사전 검사·원래 입장 버튼·정확한 플레이어·영상·출석/적립을 각각 확인한다. 과거 기록을 현재 버전의 실행으로 소급하지 않는다.
- 닥터빌 로그인 복구 뒤 작업 프로필 인증 유지·외부 플레이어 계정/개인정보 동의/추가 인증은 별도다. 사이트/팝업 범위·동의/보안·시청시간·적립 조건을 우회하지 않는다.
- 계정·프로필·시도 파일을 지우지 않는다. 에디션별 데이터/프로필/잠금과 직접 로그인 개발자3초/배포10초·자동60초/15분3회·하루10회를 유지한다.
- vendor는 v113이고 모바일 소스·APK·서명·릴리스는 변경하지 않았다. 종근당 새 로그인·설문·지속 재생·추가 사이트 반복 입장은 별도 범위다.

같은 에디션20/21/22/23/24는 작은 패치1회다. 트레이 완전 종료→resources/app 백업→패치 app 전체 교체→하단25 확인 순서이며 기존 EXE·데이터 폴더는 계속 사용한다. 첫 설치·호환 미확인 버전·runtime 변경은 전체 ZIP이다. 개발자용과 배포용을 섞지 않는다.
