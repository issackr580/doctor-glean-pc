## 마지막 수정과 검증

v14는 사전 검사를 최대8초 재판독하고 안정된 대상·버튼을 확인한다. 문서 교체는 새 문서에서 다시 읽고 로그인/provider는 대상 부재와 나눈다. 읽기 전용 검사는 계정 복구·입장·재생·예약/제출 잠금을 만들지 않으며 정시 작업·중지에 양보한다. 일괄 처리 수와 버튼 확인·시작 전 대기·로그인·확인 필요를 구분하고 판독 횟수를 남긴다.

한미 인접 날짜 묶음과 블루팜 연속 일정의 시작 날짜/시각을 PC 조회 판독 기준에 맞춘다. 한미 보완은 원래 대상/버튼/모호성 중단에만 사용하며 같은 그룹의 날짜·요일·제목·시각·숨긴 경계를 대조하고 기존5슬롯·기한·영속 기록 뒤 원래 버튼을 사용한다. 잘못된 슬롯·미신청·보안 확인은 넘기지 않는다. 블루팜의 선택일 달력 확인은 해당 날짜 범위로 보존하며 전체 조회로 승격하지 않는다. 로그인 trace에는 고정 실패 코드·navigationAllowed만 추가하고 주소·callback 값·계정·원문은 남기지 않는다.

Node173·구문, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창71·자동 작업28·계정90·PC 입장35를 확인했다. 최종 Windows 묶음 관리 창 개발자71/배포65, 같은 appData 상위 경로의 에디션 분리, 깨끗한 소스146파일 재현과13→14 동일 runtime 패치를 확인했다. [수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40467527545)에서 고정 소스·검증본 전체 파일 해시·기존 v13 SHA를 대조해 Draft에만 업로드했다. 모든 자산을 다시 다운로드해 서버 SHA·체크섬·ZIP 내부 파일 전체를 검증한 뒤 배포용만 공개했다. 개발자용은 Draft이며 독립 웹 조회로 공개/404를 확인했다. 완료한 임시 workflow는 제거했고 자동 게시·예약 실행·공개 개발자 artifact는 없다. 과거 릴리스·자산은 변경하지 않았다.

## Windows 보고와 다음 작업

1. 추가 v13 보고는15:45 시작·16:01 내보내기다. 사전 검사10건 처리는 준비 성공10건이 아니다. 키메디/인터엠디2건만 대상 확인·시작 전 대기, 닥터빌5건/메디게이트1건은 카드0, 한미/블루팜2건은 제목1·일정0이다. 사전 검사 제출0·정시 실행 근거 없음, 과거 한미5회 클릭·이동·영상 inaccessible 기록은 유지한다.
2. 디톡스 선택일 달력 checked 근거는 v13 실제 Windows에서 보존된 것을 확인했다. 닥터빌 복구는 provider·판독0·제출0·약348ms unknown, 후속 조회는 약45초 time_limit이고 기존 강의5건은 stale다. 정확한 주소/문서/응답 원인은 기존 보고서로 확정하지 않는다. 새 실패 코드·허용 주소 boolean을 다음 Windows 보고에서 확인한다. 후다닥의 이전 실패 뒤 자동 재시도 제한은 유지한다.
3. [PC 검증 방법](ENTRY_VALIDATION.md)으로 사전 검사→실제 시각/버전→클릭·이동·영상·사이트 완료를 나눠 확인한다. 실제 사용자 DOM 원인·닥터빌 로그인·이번 정시 입장·영상·적립과 미참여일 퀴즈는 재확인이 필요하다. 기존 시도 파일을 지우거나 불확실한 제출을 반복하지 않는다.
4. 모바일 v0.7.114 닥터라운지6/7·20초 분산은 PC에 미이식이며 vendor는 v113이다. mission_changed·제출0을 유지한다. 종근당 하루1회 새 로그인·닥터빌 설문·지속 재생도 해결 완료로 표시하지 않는다.

모바일 소스·APK·서명·릴리스는 수정하지 않는다. 앱 ID·프로필·Windows DPAPI·시도 기록·원래 버튼·제출 전 영속 기록·불확실 재전송 금지와 원격 창 격리를 유지한다. 패치는 같은 에디션 preview.13에만 적용하고 트레이 완전 종료→app 백업→resources/app 전체 교체→하단 버전 확인 순서를 따른다. X는 숨기기다.
