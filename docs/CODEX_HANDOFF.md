## 변경과 검증

PC-015/D25는 D24의 목록 날짜 누락 조건에서 같은 사이트/날짜/제목에 관찰된 고정 상세 링크가 하나면 시작 시각이 달라도 읽기 힌트로 사용한다. 서로 다른 ID는 기존 예약 시각과 일치하는 후보가 있어도 중단한다. 캐시로 예약이나 새 상세를 덮어쓰지 않는다. 새 상세의 독립 날짜·제목·단일 첫 시작 시각을 원래 예약과 다시 대조하며 시각만 다르면 별도 문구를 표시한다. 조회 힌트의 catalogReference=schedule_changed와 새 상세의 target_missing + scope_changed를 구분한다. scope_changed는 기존 v1 reason을 사용하며 새 기록을 실제 v25 reader로 읽는 호환을 확인했다.

사전 검사는 상세1회 GET만 허용하고 계정 복구·입장/신청 클릭·팝업/재생·필수 시도 소비를 하지 않는다. 정시 작업에 양보하고 현재 클릭/소비한 회차의 검사/경고를 추가하지 않는다. 새 사전 검사보다 오래된 실패는 이전 실행으로 표시한다. 한미 다음 슬롯은 별개다. 기존 예약 시각·기한·취소/소비·영속 시도·한미5슬롯·v1 저장·DPAPI·프로필·수동 창 보호·사이트/IPC 범위는 유지한다. 자동 재예약·기한을 지난 소급 실행은 추가하지 않는다.

개발자 opt-in TXT의 기존 entryJournal에는 고정 enum만 추가했다. 원문/URL/ID·계정·새 IPC·필수 저장 형식·자동 전송은 없다. 기존7일 동의·64회차/48event/compact256KiB·하루2000개/4MiB 한도와 꺼짐/배포용의 분리를 유지한다.

고정 입력 verify:pc는 Node247·구문·Linux Electron45/Xvfb 합성 HTTPS 관리106·자동30·계정121·입장157·replay136·신청193, Electron 전체743개를 통과했다. 시작/종료 소스·환경과 입력/결과 SHA가 일치한다. 최종 Windows resources/app의 Linux Electron 개발자106/배포92·같은 상위 appData의 분리·깨끗한 소스176파일·의존성·Node247·구문 재현·같은 에디션20/21/22/23/24/25의 실제 runtime·작은 패치 전체 app 교체가 목표 전체 ZIP과 같은12경우를 확인했다. 중간 패치는 필요하지 않다. 합성·파일 검증은 실제 Windows·DPAPI·인증 사이트 성공과 별개다.

[수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40860461062) 뒤12개 자산 재다운로드·서버 SHA·체크섬·ZIP 내부 파일 전체를 대조하고 배포용만 공개했다. 개발자 Draft·독립 웹 공개/404 경계를 확인했고 완료한 임시 workflow를 제거한다. 자동 게시·예약 실행·공개 개발자 artifact는 남기지 않는다. ## 다음 확인과 경계

- 실제 Windows에서 시각 차이 구분·단일 상세·사전 검사·원래 입장 버튼·정확한 플레이어·영상·출석/적립을 각각 확인한다. 이전 실행을 새 버전의 실행으로 소급하지 않는다.
- 사이트가 시각을 바꾼 예약의 자동 갱신은 추가하지 않았다. 기존 예약과 기한을 보존하며, 과거 실패를 새 버전 설치로 다시 실행하지 않는다. 범위를 바꾸려면 별도 실행 정책과 회귀 근거를 정한다.
- 닥터빌 로그인 복구 뒤 작업 프로필 인증 유지·외부 플레이어의 계정/동의/추가 인증은 별도다. 보안·시청시간·적립 조건을 우회하지 않는다.
- 계정·프로필·시도 파일을 지우지 않는다. 에디션 분리·직접 로그인 개발자3초/배포10초·자동60초/15분3회·하루10회를 유지한다.
- vendor는 v113이다. 모바일 소스·APK·서명·릴리스는 변경하지 않았다. 종근당 새 로그인·설문·지속 재생·추가 사이트 반복 입장은 별도 범위다.

같은 에디션20/21/22/23/24/25는 작은 패치1회다. 트레이 완전 종료→resources/app 백업→패치 app 전체 교체→하단26 확인 순서이며 기존 EXE·데이터 폴더는 계속 사용한다. 첫 설치·호환 미확인 버전·runtime 변경은 전체 ZIP이다. 에디션을 섞지 않는다.
