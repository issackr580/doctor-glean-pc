## 변경과 검증

미시도 입장 예약의 신청하기로 미신청 강의를 수강 신청한다. 한미는 미신청 조회 목록에서도 가능하다. 고정 대상·제목/날짜/시각·단일 원래 처리기를 새로 확인하고 사이트 창을 보여준다. 로그인·동의·개인 입력·결제는 사용자가 직접 한다. 신청 마침 · 상태 확인과 이후 앱의 신청 상태 확인은 읽기 전용이다. 실제 신청완료 표식만 완료로 기록한다.

registration-attempts-v1.json에 동작 전에 기록하고 양쪽 목록·재시작에서 중복 신청을 차단한다. 손상·저장 실패 시 신청 기능을 중지하고 파일을 지우지 않는다. 원래 계정/입장/진단 v1 형식은 바꾸지 않는다. 불확실 재제출0회·기한·취소/소비된 입장 기록·한미5슬롯을 유지한다. 신청 후 기존 예약을 보존하고 미소비·기한 내 미신청 예약만 다시 준비한다. 자동 중지 상태는 사용자가 해제한다.

verify:pc는 Node233·구문·실제 Linux Electron45/Xvfb 관리105·자동30·계정121·입장66·replay136(합성34시나리오)·신청193(46시나리오)을 현재 입력/결과 SHA로 확인했다. 빌드된 Windows resources/app는 Linux Electron에서 개발자105/배포91·같은 상위 appData의 에디션 분리를 확인했다. 깨끗한 소스170파일·의존성·Node233·구문 재현·21→22 동일 runtime 패치를 확인했다. 합성 통과는 실제 Windows·DPAPI·인증 사이트 성공이 아니다.

v21 회차별 선택 보고·PC 합성 재현·명시적 업데이트 확인은 유지한다. 배포용에는 개발자 추가 기록기·모듈·preload/IPC·화면을 넣지 않는다. 자동 설치·원격 규칙·진단 전송은 없다. [품질 흐름](QUALITY_WORKFLOW.md)을 따른다.

[수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40800093777) 뒤12개 자산을 재다운로드해 서버 SHA·체크섬·ZIP 내부 파일 전체를 검증하고 배포용만 공개했다. 개발자 Draft·독립 웹 공개/404 경계를 확인했고 완료한 임시 workflow를 제거한다. 자동 게시·예약 실행·공개 개발자 artifact는 남기지 않는다.
