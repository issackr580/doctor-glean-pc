## 수정과 검증

원본의 두 bounded 함수에서 이미 취소된 신호와 늦은 load/evaluate 실패가 겹치면 미처리 rejection이 되는 조건을 strict Node로 재현했다. v19는 취소/기한 뒤에도 이미 시작한 결과를 소비하며 작업을 재개하거나 제출을 반복하지 않는다. 실제 Windows 팝업의 오류명과 동일 원인은 기존 근거로 확정하지 않는다.

일반 오류보고의 runtimeFaults는 현재 프로세스 최근10개 고정 오류 종류·알려진 PC src 파일/행/열만 메모리에 보관한다. uncaughtExceptionMonitor는 Electron/Node 원래 예외 처리·팝업·종료를 유지하고 새 자동 제출을 중지한다. 처리된 예외도 원래 오류를 전달해 저장 실패와 일반 오류를 구분한다. 원문·stack·절대 경로·URL·계정·쿠키·토큰은 기록하지 않는다. 기존 계정·수동 창·시도 기록을 유지한다.

개발자용 기존7일 opt-in 기록기만 같은 최소 오류와 appVersion/sourceCommit을 기존2000개/일·4MiB 한도 안에서 보존한다. 배포용에는 추가 기록기·개발자 preload/IPC/UI가 없다. 자동 전송은 없다. 직접 제출 개발자3초/배포10초, 자동60초/15분3회, 사이트별 하루10회와 불확실 자동 재제출 중단은 유지한다.

Node201·구문, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창78·자동 작업30·계정103·입장54를 통과했다. 최종 Windows 묶음 관리 창 개발자78/배포72·같은 appData 상위 경로의 에디션 분리, 깨끗한 소스155파일 재현·18→19 동일 runtime 패치를 확인했다. [수동 업로드](https://github.com/issackr580/doctor-glean-pc/actions/runs/40644682408)는 고정 소스·검증본 전체 파일 해시·이전 자산 SHA를 대조해 기존 두 Draft에만 업로드했다. 전 자산을 재다운로드해 서버 SHA·체크섬·ZIP 내부 파일 전체를 검증한 뒤 배포용만 공개했다. 개발자 Draft·독립 웹 공개/404 경계를 확인했다. 완료한 임시 workflow를 제거하며 자동 게시·예약 실행·공개 개발자 artifact는 남기지 않는다.

## 다음 작업과 경계

- 실제 Windows 팝업 재발 시 가능하면 완전 종료 전에 일반 오류보고를 저장한다. 개발자 opt-in 기록기는 해당 최소 오류를 재시작 뒤에도 남길 수 있다. 사이트 자체의 모든 alert·Windows 오류를 포괄하지 않는다.
- Windows의 실제 인증·조회 범위·일정/중복 판독·정시 입장·영상/적립은 별도 실사용 검증 대상이다. 합성 통과를 실제 성공으로 확대하지 않는다. [PC 검증 방법](ENTRY_VALIDATION.md)을 따른다.
- vendor v113을 유지하며 모바일 변경을 PC에 반영된 것으로 가정하지 않는다. 모바일 소스·APK·서명·릴리스·개인 Chrome/Edge 프로필은 수정하거나 가져오지 않는다. 종근당 새 로그인·설문·지속 재생은 별도 범위다.
- DPAPI·사이트/에디션별 프로필·제출 전 영속 기록·기한·불확실 재제출 중단을 유지한다. 계정/시도 파일을 지우거나 실패를 성공으로 완화하지 않는다.

패치는 같은 에디션 preview.18에만 적용한다. 트레이 완전 종료→resources/app 백업→패치 app 전체 교체→하단 버전 확인 순서다. X는 숨기기다. 첫 설치·다른 버전은 전체 ZIP이다.
