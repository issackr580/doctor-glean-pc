# 버튼 업데이트

preview.28부터 Windows x64 실행판에서 지원한다. 처음 preview.28로 올릴 때만 기존과 같이 같은 에디션의 작은 패치를 적용한다. 이후에는 앱 하단의 **PC 업데이트 확인 → 다운로드·업데이트**를 누른다. 프로그램이 파일을 받고 검증한 뒤 완전히 종료·교체·재시작한다. 로그인·설정·예약·시도 자료는 같은 에디션의 별도 데이터 폴더에 유지한다. 자동 확인/설치는 하지 않는다.

배포용은 공개 파일을 바로 받는다. 개발자용은 업데이트 전용 GitHub 창이 열리면 관리자/쓰기 권한 협업자 계정으로 직접 로그인하고 필요한2단계 인증을 마친다. 이미 로그인된 세션은 전용 프로필에서 재사용한다. 비밀번호·PAT를 앱에 따로 입력하거나 저장하지 않는다. 다른 사이트 로그인·Chrome/Edge 프로필과 공유하지 않는다. 개발자용 파일은 계속 비공개 Draft이며 권한이 없으면 설치하지 않는다. 로그인 창을 닫으면 취소한다. 실제 GitHub 로그인/추가 인증은 별도 확인이다.

강의 입장·계정·조회 작업이나 직접 사용하는 사이트 창이 있거나2분 안에 입장이 예정됐으면 다운로드한 뒤 설치를 미룬다. 해당 작업/창을 마친 뒤 **업데이트하고 재시작**을 누른다. 강의를 끊기 위해 강제 종료하지 않는다. 설치 후 새 관리 UI가 준비되기 전에는 새 자동 동작을 시작하지 않는다.

서명·해시가 맞지 않거나 다른 에디션/버전이면 설치하지 않는다. 실행 환경이 달라지면 공식 전체 묶음을 안내한다. 쓰기 권한 없는 설치 폴더는 자동으로 관리자 권한을 요구하지 않는다. 쓰기 가능한 폴더에서 실행하거나 전체 묶음을 사용한다. 새 앱 시작이 실패하면 이전 app을 복구하고 오류를 표시한다. 성공한 업데이트의 이전 app 백업은 resources의 전용 업데이트 폴더에 보관한다. 예기치 않은 전원 종료/디스크 손상 등 자동 복구가 불가능한 경우 완전 종료 후 백업 app으로 수동 복구할 수 있다. 기존 앱 데이터/시도 파일은 삭제하지 않는다.

## 유지보수와 서명 피드

기존 Windows 실행파일 코드서명과 별도로 Ed25519 업데이트 서명을 사용한다. 공개키만 src/update-trust.js에 고정하며 개인키는 관리자가 저장소·소스 ZIP·앱·공개 workflow 밖에 보관한다. 서명 키가 없는 환경에서도 빌드/수동 배포는 가능하며 서명된 버튼 업데이트 피드를 발행했다고 주장하지 않는다.

1. 새 버전의 검증·깨끗한 소스·두 에디션 빌드·전체/작은 패치/소스 ZIP을 확인한다. runtime과 전체 app 교체가 목표와 같은 버전만 compatibleVersions에 기록한다.
2. 기존 배포 절차에 따라 자산을 올리고 전체 파일을 재다운로드해 서버 SHA·체크섬·ZIP 내부를 대조한다. 배포용만 공개하고 개발자용은 Draft로 유지한다.
3. 실제 서버 자산의 버전·이름·SHA/크기·원래 GitHub 다운로드 URL·소스 commit·같은 에디션 호환 버전으로 schemaVersion1 payload를 만든다. 공개 피드는 계정·PAT·쿠키·CDN의 일회용 주소를 포함하지 않는다. 개발자 Draft의 원래 불투명 경로와 파일 해시가 공개돼도 파일 접근 권한은 부여되지 않는다.
4. 저장소 밖의 개인키로 서명한 피드만 PR로 updates/preview.json 또는 stable.json에 기록한다. 서명 뒤 다시 공개키로 검증하고 실제 자산과 대조한다. 피드/문서 인계만 갱신하며 이미 발행한 실행 소스·태그·자산을 교체하지 않는다. updates는 실행 소스 export 대상에 포함하지 않는다.

```sh
node scripts/sign-update-feed.mjs --input=/private/payload.json --key=/private/update-key.pem --output=updates/preview.json
```

피드의 targets는 에디션별 version/electronVersion/sourceCommit/page/compatibleVersions/patch(name,sha256,size,url)만 포함한다. 원격 코드/규칙/셸/파일 경로를 지정하는 설정이 아니다. 새 업데이트 회귀는 npm run test:electron -- --suite=update이며 기존 전체 verify:pc에 포함한다. Linux 실제 Electron/합성 HTTPS는 Windows 적용·실제 GitHub 로그인·사이트 입장 성공을 대체하지 않는다.
