# 의사 이삭 줍기 PC 구현 순서

Windows용 독립 실행기를 작은 단계로 검증한다. 기존 Android 제품과 배포물은 그대로 두고 별도 폴더에서 작업한다.

2026년 10월 26일 0.1.0-preview.7 기준. 계정 제출 후 문서 전환의 검증 바인딩 오류를 재현·수정하고, 인증 팝업·다음 시도 시각·단계 진단과 저장 후 작업 프로필 확인/조회 갱신을 연결했다. 사용자 Windows 보고에서5사이트 계정 저장을 확인했으나 나머지 사이트의 실제 성공은 추가 확인이 필요하다.

공동 개발은 CONTRIBUTING, STATUS, ARCHITECTURE, DECISIONS, RELEASE_PROCESS를 기준으로 한다. 공개 소스·distribution 실행파일은 PC 전용 GitHub 저장소에서 관리하고, 본인용 developer 실행물은 별도 개인 초안으로 유지한다. 소스 기준 커밋·태그·문서·묶음을 같은 PC 저장소에 연결한다. Node/합성 Electron과 실제 Windows 근거를 구분하고 Android 원본과 기존 릴리스를 변경하지 않는다.

## 1 기반

- 로컬 관리 창, 트레이 열기·중지·종료, 같은 Windows 사용자에서 한 프로세스만 실행.
- 사이트별 전용 프로필과 직접 로그인 창. 임의 주소·파일·셸 실행 API는 만들지 않는다.
- 한국 시간 날짜·예약 계산, 영속적인 제출 시도 기록, 중지와 오래된 작업 차단.
- 원본 엔진의 명시적 스냅샷과 출처 해시. 아직 자동 제출·입장에는 연결하지 않는다.
- 통과 기준: Node 정책 검사, 저장 실패·프로세스 중단 재현, UI 권한 경계 확인. 실제 Windows 동작은 별도 필수 확인.

## 2 강의 조회

- 닥터빌·키메디부터 판독 엔진과 PC 페이지 수명주기를 연결하고 나머지 사이트를 순차 추가.
- 로그인된 창과 자동 조회의 저장소 공유 확인, 날짜·시각·제목·빈 목록·페이지 이동·취소 검증.
- 새로고침 실패 시 유효 목록 보존, 미완료 상태 구분, 목록 복사.
- 통과 기준: 실제 Windows PC에서 사용자 화면과 수집 결과 대조. 첫 사이트 통과를 전체 사이트 지원으로 확대하지 않는다.

## 3 당일 작업

- 출석·캡슐·퀴즈 상태 확인부터 연결한 뒤 원래 버튼 실행.
- 닥터빌 하루 1회 자동 퀴즈, 브랜드관의 원래 대기·선물 버튼·2회 제한 유지.
- 명시적으로 켠 기능만 실행. 저장 실패 시 0클릭, 결과 미확인 시 재제출 0회.
- 통과 기준: 실제 성공 안내, 이미 완료한 날, 대상 없는 날, 클릭 직후 연결 단절·재시작, 로그인 만료 확인.

## 4 자동 입장

- 사이트별 입장 정책과 직접 입장·취소·다시 예약·기한을 이식.
- 한미 준비 확인과 시작 기준 5회 슬롯을 구분하고, 종료된 강의에 추가 진입하지 않는다.
- 조회·당일 작업과 충돌할 때 입장을 우선하되 수동 로그인 창은 보호.
- 통과 기준: 실제 Windows 입장 버튼과 목적지 확인. 영상 페이지 진입과 재생 확인을 별도로 기록.

## 5 예약 실행과 배포

- 오전 실행과 평일 자정 작업, 설정별 켜기·끄기, 한국 날짜 변경·재시작 복원.
- 정시 직전 준비, 시도 전 저장, 유효기한 종료. 절전이나 종료로 놓친 기한은 소급하지 않는다.
- 수동 업데이트용 Windows 묶음과 사용 안내·변경 내역·체크섬 생성.
- 통과 기준: 실제 Windows에서 야간 무인 실행 결과·단계 시각을 확인하고, 지원 범위를 정확히 표시.

## 개발 실행

```sh
npm ci
npm test
npm run check
npm start
```

현재 단계·검증 결과는 README.md에 기록한다. Node 검사 통과는 Windows 실행·사이트 로그인·실제 적립 성공을 대신하지 않는다.
