# 0.1.0-preview.18 — 직접 재시도 대기 단축과 비동기 로그인 이동

2026-10-27. Windows PC판 수정이며 검증한 고정 소스에서 두 에디션을 준비한다.

## 실제 Windows 근거

새 TXT/개발자 JSON은 v17 소스38e10e9·22:38 시작·22:43 내보내기이며 내보낸 시각 외 현재 상태가 같다. 닥터빌 복구는229ms·판독0·제출0의 policy_rejected이고 providerPath=other/callbackState=missing이다. v17의 기본 경로 복구는 호출되지 않았으며 기존5강의는 stale다. 정확한 다른 제공자 경로는 이전 enum으로 특정하지 못한다.

사용자는 직접 엠써클 로그인을 마치면 자연스럽게 닥터빌 메인까지 이동하고 팝업이 뜬다고 확인했다. 다른6사이트의 이번 저장 계정 복구에서는 인증을 확인했으며 디톡스1·키메디2 강의를 읽었다. 입장16건은 이전 보고와 같고 새 정시 검사/클릭은 없다. 출석/퀴즈의 기존 완료를 새 PC 제출로 해석하지 않는다. 개인 원본은 커밋하지 않는다.

사용자는 로그인 실패 후 약10분 대기가 특히 개발자용에서 부적절하다고 지적했다. 기존 앱은 직접 요청과 자동 복구를 같은15분3회·60초 간격에 묶었고, Manager의 선행 검사 때문에 단순 현재 세션 확인도 막았다.

## 변경과 유지 조건

- 직접 로그인 제출 간격을 개발자용3초·배포용10초로 분리한다. 직접 요청에는15분3회 자동 복구 제한을 적용하지 않는다. 사이트별 하루10회 한도는 공통이다. 자동 복구는 기존60초·15분3회·거절/불확실 뒤 자동 재제출 중단을 유지한다. 새 버전·재시작·성공 재저장으로 한도를 지우지 않는다.
- 대기/당일 한도 상태라도 저장 계정 복구에서 현재 세션을 읽을 수 있다. 이미 인증됐으면 비밀번호 복호화·제출·새 시도 예약 없이 끝난다. 로그인 입력이 필요하면 기존 두 준비 판독 뒤 실제 영속 reserve에서 제한을 재확인한다. 후보 저장·거절 잠금·수동 창 보호·DPAPI는 유지한다.
- 제공자 SPA가 callback 없는 중간 경로로 바뀐 뒤 비동기 이동하는 동안 즉시 일반 credential 판독을 호출하지 않는다. 정확한 기존 제공자 origin에서만 최대20회×400ms 동안 이동을 수동 관찰한다. 이 대기는 스크립트 실행·비밀번호·클릭·추가 GET/POST를 수행하지 않고 기존90초/제출 후20초 기한을 늘리지 않는다. 잘못된 callback·외부 origin·제출 전 후보에는 적용하지 않는다. 끝나지 않은 이동은 기존 정책대로 중단한다.
- 허용 화면이 돌아와도 준비 판독을 새로 시작하고 URL·문서 세대를 함께 확인한다. 입력/인증 허용 주소는 넓히지 않는다. 제공자 경로는 공개 코드의 고정 enum과 providerSettling boolean만 기록하며 주소·query·일회용 토큰 값은 없다.
- v1 계정/시도 스키마를 유지한다. 현재 날짜 최대10개와 자동 rolling 판단에 필요한 최근3개를 포함하는 최대13개로 유지하며 제한 판단에 필요한 기록을 보존한다. 자동/직접 재시도 가능 시각과 현재 세션 확인을 구분해 표시한다. 실제 v17 reader의 읽기/다시 저장과 당일 한도 보존을 확인했다.

## 검증과 한계

v17 원본에서 비동기 이동의 조기 실패·직접 요청의 긴 대기를 재현했다. Node190·구문, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창72·자동 작업28·계정103·입장54를 통과했다. 지연된 인증 상태·다시 표시된 폼·제출 후 이동·끝나지 않은 이동·변형 callback·후보 제외, 새 준비 판독·영속1회 제출·대기/당일 한도의0제출 세션 확인·자정 기록 경계를 검증한다. 최종 묶음·소스·17→18 패치와 게시 검증 결과는 완료 뒤 추가한다.

실제 Windows의 다른 제공자 경로와 v18 자동 복구 성공은 재확인이 필요하다. 합성 재현을 이번 정시 입장·영상·적립 성공으로 확대하지 않는다. v17의 일정/중복/블루팜 보완과 미확인 범위를 유지한다. 모바일·vendor v113·의존성·Electron45·기존 계정/프로필·입장/포인트 시도와 과거 자산은 변경하지 않는다.
