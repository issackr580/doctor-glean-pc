# 0.1.0-preview.19 — 취소 중 오류와 팝업 진단

Windows PC판만 변경한다. Electron45.0.0·vendor v113·모바일 소스/APK/서명/릴리스·기존 계정/프로필·외부 시도 파일은 유지한다.

## 근거와 범위

사용자의 v18 개발자 Windows 보고는10월27일23:36 시작,10월28일14:49 JSON/15:09 TXT 내보내기이며 시각 외 현재 상태가 같다. 팝업 문구/주 프로세스 예외 근거는 없고 사용자는 문구를 기억하지 못한다고 확인했다. 현재 자료로 원래 팝업의 오류명·원인을 확정하지 않는다. 과거10월26일의 popup_blocked를 이번 팝업으로 해석하지 않는다. 개인 원본은 커밋하지 않는다.

v18 원본의 두 bounded 함수에서 취소 신호가 이미 켜졌을 때 load/evaluate Promise를 관찰하지 않는 경로를 재현했다. 뒤늦은 reject가 strict Node에서 프로세스 오류가 되는 조건이며 이번 Windows 팝업과 동일 원인인지는 미확정이다. 취소·기한이 먼저 끝나도 시작한 비동기 작업의 resolve/reject를 끝까지 소비하도록 공통 함수를 연결한다. 외부 재제출·권한 확대·취소한 작업의 재개는 하지 않는다.

일반 오류보고에 현재 프로세스 최근10개 고정 오류 종류·검토된 PC 소스 파일/행/열을 메모리로만 추가한다. 주 프로세스 uncaughtExceptionMonitor는 원래 Electron/Node 예외 처리·팝업·종료를 유지하고 자동 제출부터 중지한다. 자동 작업의 처리된 예외도 원래 오류를 전달해 실제 저장 실패와 일반 실행 오류를 구분하고 고정 코드로 안내한다. 기존 수동 창·계정·시도 기록을 삭제하지 않는다.

개발자용 기존7일 opt-in 기록기만 같은 최소 오류와 appVersion/sourceCommit을 기존2000개/일·4MiB 한도 안에서 보존한다. 배포용에는 추가 기록기·개발자 preload·전용 IPC/UI를 넣지 않는다. 원문 메시지·stack·절대 경로·URL·계정·쿠키·토큰은 기록하지 않고 자동 전송하지 않는다. 시작/관리 로드 오류와 알림 Promise도 명시적으로 처리한다.

## 실제 Windows 관찰과 남은 문제

- 닥터빌의 account_home/missing 화면에서 수동 관찰 뒤 약1.3초에 기존 세션 인증을 읽었다. 제출0회이며 비밀번호 자동 제출 성공으로 바꾸지 않는다. 목록8건과 출석·퀴즈 기존 완료를 관찰했다.
- 이번 실행에서 키메디13:00 클릭/이동1회·인터엠디13:00 클릭/이동2회·한미13:10~13:50의5슬롯 클릭/이동을 확인했다. 한미 영상 inaccessible이며 영상/적립은 미확인이다. 슬롯별 영속 unknown은 사이트 완료를 확정하지 않는 잠금이다.
- 닥터빌 점심3예약은 제목/일정 대조 실패, 메디게이트는 duplicate_target로 미클릭이다. 디톡스는 복구 인증 뒤 조회 time_limit이고 기존 목록이 stale로 남았다. 이 팝업 수정에서 판독을 임의 완화하지 않는다.
- 출석4곳·닥터빌/인터엠디 퀴즈는 기존 완료 판독·새 제출0회다. 브랜드관은 배너 없음 종료, 닥터라운지는 mission_changed·제출0을 유지한다. 저녁 예약 결과는 내보내기 시점에 없다.

## 검증·배포

Node201·구문, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창78·자동 작업30·계정103·입장54를 통과했다. 취소 전/후의 늦은 reject·실제 native load/evaluate 창 파기·기본 예외 처리 유지·오류의 안전한 필드/위치·기록기 off/재시작·기존 외부 시도와 수동 창 보존을 확인했다. 최종 Windows 묶음·깨끗한 소스·18→19 동일 에디션 패치와 게시 검증을 진행한다. 실제 Windows 팝업의 재발/오류 코드·사이트 계정/정시 입장·영상/적립은 추가 실사용 확인 대상이다. 과거 공개 자산은 덮어쓰지 않으며 개발자 실행물은 협업자 전용 Draft로 유지한다.
