# 0.1.0-preview.20 — 수동 로그인과 상세 재확인

Windows PC판만 수정한다. 개인 보고 원본·실사용 시각·사이트별 활동 내역은 공개 기록에서 제외하고 구현·합성 검증·배포 근거만 남긴다.

## 변경

- 수동 로그인: 기존 credential registry의 고정 로그인 주소를 모든 사이트의 메뉴/관리 화면에 연결한다. 주소 누락으로 invalid_site 예외가 나는 경로와 닫힌 창의 늦은 메뉴 호출을 보완한다. 기존 허용 origin·원격 창 격리·프로필을 확대하지 않는다.
- 한미: 공개 처리기의 원래 loginProcess POST를 기존 Network 개수·HTTP 상태 관찰에 포함한다. 실제 정상 인증 응답·제출 ACK·새 결과 문서·검토한 충돌 조건을 모두 확인할 때만 고정 보호 목록을1회 GET하고 그 문서의 기존 인증 근거를 요구한다. 결과 화면의 로그아웃 표시와 비밀번호 입력란만으로 저장하지 않는다. 비밀번호 변경·추가 인증·실패 응답·다른 결과 경로·중복 POST는 중단하고 재제출하지 않는다.
- 닥터빌: 목록의 일정 대조가 불충분하면 단일 제목 카드에서 관찰한 고정 seminarId 상세 링크만1회 읽는다. 이 이동은 입장 클릭이 아니다. 상세 문서의 제목·실제 날짜·첫 시작시각·원래 버튼을 PC 판독으로 다시 대조한 뒤 기존 영속 제출 권한을 사용한다. 원래 엔진의 상세 이동에도 같은 엄격한 대조를 적용해 제목 날짜·끝 시각을 일정 근거로 삼지 않는다. 중복 제목·위험한 링크·잘못된 일정은0클릭이고 사전 검사는 이동하지 않는다.

## 유지하는 경계

Windows DPAPI·후보 격리·수동 창 보호·사이트/에디션별 앱 ID/프로필·전체/기능 동의·제출 전 영속 기록·정해진 기한·한미5슬롯·불확실 자동 재제출 중단을 유지한다. 직접 제출 개발자3초/배포10초, 자동60초/15분3회·사이트별 하루10회와 기존 파일 형식을 유지한다. 로그/원문/URL/계정/토큰은 배포물에 넣지 않고 자동 전송하지 않는다. 모바일 소스·APK·서명·릴리스·vendor v113·Electron45·의존성과 과거 자산은 변경하지 않는다.

## 검증과 한계

Node205·구문, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창84·자동 작업30·계정121·입장66을 통과했다. 수동 로그인 메뉴/닫힌 창·한미 정상 응답/후보/복구/추가 인증/실패 응답·닥터빌 상세의 날짜/첫 시각/제목 날짜/중복/위험 링크를 검사했다. 실제 v19 reader의 읽기/다시 저장 호환도 확인했다. 최종 Windows 묶음 관리 창 개발자84/배포78·에디션 분리, 깨끗한 소스156파일의 의존성 설치·Node205·구문 재현·19→20 동일 runtime 패치를 확인했다. 실제 Windows의 로그인·정시 입장·영상·적립과 보호된 실제 DOM은 별도 재확인 대상이다. 합성 통과를 실계정 성공으로 확대하지 않는다. 공개 페이지/원래 처리기로 고정 진입점과 POST 경로는 확인했지만 인증된 실제 화면은 확보하지 않았다.

같은 에디션 preview.19만19→20 패치를 사용한다. 트레이 완전 종료→resources/app 백업→패치 app 전체 교체→하단 버전 확인 순서다. 다른 버전·첫 설치는 전체 ZIP이다. 개발자 실행물은 협업자 전용 Draft로 유지한다.
