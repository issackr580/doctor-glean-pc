# 0.1.0-preview.9 디톡스 로그인 판독

2026-10-27. 실행파일 소스는 `pc-source-v0.1.0-preview.9`과 빌드 manifest의 commit을 기준으로 한다.

## 문제와 결과

v8 사용자 보고에서 닥터빌은 저장됐다. 디톡스는 실제 로그인 POST1회·HTTP302 뒤 보호 목록까지 도착했지만 닫힌 프로필 메뉴 안의 로그아웃 표시를 못 찾아 약46.6초 시간 초과였다. 사용자는 직접 로그인과 메뉴 안 로그아웃 표시를 확인했다.

- 공개 CSS로 확인한 서버 프로필 상자의 정확한 로그아웃 요소와 안전한 목적지/원래 함수 참조를 읽는다. 메뉴·로그아웃·함수·접근자를 실행하지 않는다.
- 후보 저장에는 네이티브 실제 인증 요청/정상 응답, 제출 ACK,1회 보호 목록 재확인과 로그인/비밀번호 충돌 없음도 필요하다. 숨겨진 템플릿·302·주소만으로 성공을 만들지 않는다.
- 이미 인증된 작업 프로필은 추가 복호화/로그인 없이 확인하며 수동 창과 자동 작업도 같은 판독 범위를 사용한다.
- 수동 고정 목록 GET 실패는 고정 로그인 GET을1회 연다. 양쪽 실패는 재시도 창을 유지하고 정상 중단된 이동은 오류로 바꾸지 않는다.
- 기존9계정, 시도 이력, 에디션/사이트별 데이터·ID, 원격 격리와 TLS 검증을 유지한다. 포인트·강의 기능으로 범위를 넓히지 않는다.

## 검증과 남은 확인

Node128·구문 검사와 Linux Electron 합성 HTTPS 계정50항목 통과. 닫힌 메뉴 후보 검증,1회 POST/보호 GET, 기존 세션0회 복호화/재제출, 제출/응답 근거 누락·로그인 충돌·다른 origin/base·접근자 거부·함수 미실행·경로 제한과 비밀정보 제외를 검사했다. 최종 두 빌드 관리 창과 자동 작업·다운로드 SHA는 검증 후 기록한다.

사용자 Windows에서9계정 저장이 보고됐다. 디톡스의 이번 수정 뒤 실제 저장·새 로그인 복구 성공은 사용자 재확인 단계다. 실제 Windows 계정 검증을 합성 검사로 대신하지 않는다.

## 업데이트

같은 에디션의8→9 작은 패치를 사용한다. 프로그램 완전 종료 → resources/app 백업 → app 전체 교체 → 버전 확인 순서다. 배포용은 공개 릴리스, 개발자용은 지정 collaborator 전용 Draft다. 기존 릴리스/태그/자산과 Android는 변경하지 않는다.
