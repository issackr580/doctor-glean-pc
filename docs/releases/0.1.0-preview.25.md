# PC 0.1.0-preview.25 — 날짜 누락의 기존 조회 상세 재확인

목록의 제목 후보와 전용 시작 필드는 있지만 날짜가 없을 때, 수집기에는 같은 날짜의 단일 상세 링크가 남아도 입장/사전 검사가 멈추는 조건을 재현했다. 기존 CatalogStore의 사이트·날짜·제목·시작시각이 같은 단일 관찰 링크를 고정 seminarDetail GET의 참고로 사용한다. 복수 식별 링크·unsafe URL은 중단하며 캐시의 날짜만으로 입장하지 않는다. 새 상세의 제목·독립된 날짜·첫 시작시각·원래 버튼을 다시 대조한다.

사전 검사도 동일한 상세1회 읽기를 허용하지만 계정 복구·입장/신청 클릭·팝업/재생·필수 시도 소비는 하지 않고 정시 작업에 양보한다. 이미 클릭/소비한 현재 회차에는 사전 검사/경고를 추가하지 않으며 실제 실행 기록과 미확인 재생/적립을 유지한다. 한미 다음 슬롯은 별개로 검사할 수 있다. 새 검사에서 대조를 통과한 예약의 과거 실행 경고는 이전 결과로 표시한다.

개발자용의 진단을 켠 동안 일반 TXT 오류보고에도 기존 entryJournal을 포함해 날짜 누락/시각 오류·catalog 참고의 missing/matched/ambiguous/unsafe를 고정 개수/enum으로 내보낸다. 꺼짐·배포용에는 추가하지 않는다. 기존7일 동의·64회차/48event/compact256KiB·하루2000개/4MiB 한도·명시적 내보내기를 유지하고 원문 날짜/제목·URL/ID·계정·새 IPC·필수 저장 형식·자동 전송은 추가하지 않는다.
