# 0.1.0-preview.15 — 로그인 진입점과 조회·입장 판독 일치

2026-10-27. 배포용 공개 prerelease와 개발자용 협업자 전용 Draft 게시를 완료했다.

## Windows 보고와 변경

추가 v14 보고는16:36 시작·16:54 내보내기이며 TXT/개발자 JSON은 내보낸 시각 외 현재 상태가 같다. 조회9곳을 마쳤고 디톡스 선택일 달력·블루팜 선택일 달력 확인 근거를 보존했다. 일괄 사전 검사10건은 로그인5·시작 전 대기2·미확정3이다. 닥터빌5건은 로그인, 키메디·인터엠디는 대상 확인 후 시작 전 대기, 한미·블루팜은 제목1·일정0, 메디게이트는 대상2개다. 새 정시 입장 근거는 없고 과거 한미 클릭5회는 이번 성공으로 소급하지 않는다.

닥터빌은 제출 전 약185ms·판독0의 `policy_rejected`이며 provider origin은 허용됐지만 navigationAllowed/loginRoute는 false다. 비밀번호 제출 실패로 해석하지 않는다. 사용자는 수동 로그인 창이 정상이라고 확인했다. 자동 진입 URL은 snapshot의 비인코딩 형태였고 수동 창은 인코딩된 고정 형태다. v15는 수동 창과 같은 고정 진입점으로 통일한다. Linux 익명 공개 GET 관찰에서는 이전 형태도 정상 login/callback이었으므로 Windows의 정확한 주소 정책 불일치 원인을 해결 완료로 단정하지 않는다.

- 한미의 기존 조회기는 제목 앞 클래스 없는 시각을 지원했지만 v14 PC 입장 보완은 `.top .time`만 읽었다. 같은 합성 DOM에서 조회 성공·입장 실패를 재현했다. v15는 같은 인접 날짜 묶음의 제목 앞 최소 시각 필드를 읽고 날짜·요일·충돌·숨긴 경계·다시보기 영역을 확인한다. 기존5슬롯·기한·제출 전 영속 기록 뒤 원래 버튼을 사용한다.
- 블루팜 기존 조회기는 최소 일시 필드를 선택하지만 v14 PC 입장 보완은 연자·포인트가 섞인 전체 메타데이터를 읽어 일정을 거부했다. 같은 DOM으로 재현했고 v15는 최소 일시 필드를 선택한다. 시작이 같아도 다른 일정 필드는 합치지 않고 잘못된 종료·시작 시각 부재를 거부한다.
- 닥터빌 자동 로그인의 고정 진입점을 통일하고 제출 전 정책 거절은 blocked로 구분한다. 제출 후 불확실 중단·인증 근거·복호화 시점·callback/경로 제한은 유지한다. trace는 providerPath/callbackState의 고정 enum만 추가하며 주소·값·계정은 남기지 않는다.

## 검증과 한계

Node176항목·구문, 실제 Linux Electron45/Xvfb 합성 HTTPS 관리 창71·자동 작업28·계정91·PC 입장43항목이 통과했다. 같은 실제 DOM에서 원래 조회기와 PC 입장기의 한미/블루팜 판독이 수정 전 불일치·수정 후 일치함을 확인했다. 잘못된 날짜/요일·복수 시각·제목 뒤 시각·다시보기·복수 일정은 거부한다. 한미 원래 버튼은 슬롯별 제출 전 기록 뒤1회만 호출하고 다음 슬롯은 보존한다. 닥터빌은 정확한 수동 진입점·제출 전 복호화 제한·제출 뒤 불확실 처리와 enum의 비밀값 제외를 검증했다.

최종 Windows 묶음 관리 창 개발자71/배포65·같은 appData 상위 경로의 에디션 분리, 깨끗한 소스147파일의 의존성 설치·Node176·구문 재현과14→15 동일 runtime 패치를 확인했다. 합성 검사를 실제 Windows 로그인·이번 정시 입장·영상·출석/적립 성공으로 확대하지 않는다. 메디게이트 대상2개와 후다닥의 이전 실패 후 자동 재시도 제한은 남는다. 메디게이트의 entryControls0은 모호성 조기 중단 결과여서 실제 버튼 부재로 단정하지 않는다. 실제 사용자 DOM 일치와 닥터빌 SSO 재확인이 필요하다.

모바일·vendor·의존성·Electron45·기존 계정/프로필/시도 파일과 과거 자산은 변경하지 않는다. 닥터라운지 v114 이식·지속 재생·시청시간/적립 우회는 추가하지 않았다. 개인 보고서·공개 페이지 원문은 소스에 넣지 않는다.
