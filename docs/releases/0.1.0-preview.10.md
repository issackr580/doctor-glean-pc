# 0.1.0-preview.10 작업 중 — 키메디 저장 계정 복구

2026-10-27. 공개 실행판은 preview.9이며 이 수정은 아직 빌드·게시하지 않았다.

## 문제와 변경 후 동작

Windows v9에서 키메디 저장 계정 복구가 한 번 제출된 뒤 홈 화면에서 인증 근거를 확인하지 못하고 시간초과했다. PC CredentialRunner가 복구 요청에 `validation:false`를 포함했지만, 원본 background proof는 validation 필드가 없는 저장 계정 복구만 허용하므로 서버 회원 확인을 시작하지 못했다.

후보 검증 요청에는 `validation:true`와 후보 제출 여부만, 저장 계정 복구 요청에는 background 옵션만 전달한다. 원본 vendor를 수정하지 않는다. 실제 서버 회원 응답을 한 번 확인해야 인증 성공이며 토큰·이동·제출만으로 성공하지 않는다. 실패·불확실 결과의 자동 재제출 금지와 제출 전 기록을 유지한다.

## 검증

- Linux, Node24.19.0/npm11.9.0, 고정 Electron45.0.0과 기존 lockfile로 `npm ci`를 실행했다.
- `npm test` 실제131항목 통과, `npm run check` 통과. 초기 제한 샌드박스에서는 자식 IPC 제약으로 파일17개만 집계됐으므로 그 결과를 제품 항목 통과로 쓰지 않았다. IPC가 허용되는 실행 환경의 기본 명령과 `--test-isolation=none` 실행에서 각각131항목을 확인했다.
- 원본 background helper를 사용하는 회귀3항목은 기존 코드에서 시간초과·서버 확인0회를 재현했고 수정 뒤 통과했다. SPA/새 문서, 서버401/빈 회원 응답, 제출 전 영속 기록, 복호화/제출/서버 확인 각1회, 진단의 비밀정보 제외와 실패 후 자동 재제출 차단을 검사했다.
- `npm run test:electron -- --container-no-sandbox`: 실제 Linux Electron·Xvfb의 합성 HTTPS에서 개발자 관리 창60·자동 작업20·계정60항목 통과. 키메디3경로의 원래 폼 처리기와 서버 확인에 대한10개 관찰을 추가했다. 배포용 빌드 검사는 이번에 실행하지 않았다.
- 컨테이너의 OS sandbox 구성 제약으로 위 옵션은 검사 프로세스에만 사용했다. 제품의 remote sandbox·contextIsolation·TLS 검증은 유지한다. 합성 계정만 사용했으며 Windows DPAPI·실제 키메디 계정의 복구는 이 환경에서 검증하지 않았다.

## 별도 남은 확인

- 후다닥은 차단된 이동과 로그인 화면 복귀가 보고됐지만 정확한 목적지를 진단만으로 알 수 없다. 허용 범위를 추측해 넓히지 않았다.
- 닥플 플러스는 앞선 인증 판독 뒤 재시도 대기와 사용자 수동 로그인이 보고됐다. 세션 유지·추가 복구가 필요한 조건은 재확인 대상이다.
- 사용자는 당일 출석·퀴즈를 모바일에서 먼저 처리했다. PC의 완료 판독과 새 자동 제출을 구분한다. 닥터빌의 대상 링크 모호성은 유지하며 미참여일 실제 제출은 미검증이다.
- 모바일 v114 닥터라운지 이식, APK·서명·모바일 릴리스는 변경하지 않았다. PC 에디션 ID·사용자 자료·시도 기록·Electron45.0.0·의존성 해시를 유지한다.
