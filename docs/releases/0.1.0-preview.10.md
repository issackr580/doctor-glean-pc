# 0.1.0-preview.10 — PC 로그인 복구와 닥터빌 퀴즈

2026-10-27. 배포용 공개 prerelease와 개발자용 협업자 전용 Draft 등록을 완료했다. 실행 소스는 `2aef5b3235f5875196983c5b6581c7731418f30f`, 소스 태그는 `pc-source-v0.1.0-preview.10`이다. 게시 확인 문서는 이 소스 기준점 이후이며 공개 ZIP을 교체하지 않는다.

## 문제와 변경 후 동작

Windows v9에서 키메디 저장 계정 복구가 한 번 제출된 뒤 홈 화면에서 인증 근거를 확인하지 못하고 시간초과했다. PC CredentialRunner가 복구 요청에 `validation:false`를 포함했지만, 원본 background proof는 validation 필드가 없는 저장 계정 복구만 허용하므로 서버 회원 확인을 시작하지 못했다.

후보 검증 요청에는 `validation:true`와 후보 제출 여부만, 저장 계정 복구 요청에는 background 옵션만 전달한다. 원본 vendor를 수정하지 않는다. 실제 서버 회원 응답을 한 번 확인해야 인증 성공이며 토큰·이동·제출만으로 성공하지 않는다. 실패·불확실 결과의 자동 재제출 금지와 제출 전 기록을 유지한다.

후속 수정은 후다닥·닥플 플러스 복구와 닥터빌 자동 퀴즈를 포함한다.

- 후다닥의 고정 PC 목록 로드 실패는 원래 로그인 GET을1회 연다. 제출 ACK·실제 인증 응답 뒤 이동이 차단되면 고정 PC 페이지를1회 다시 읽고 그 페이지의 인증 근거를 요구한다. 새 호스트나 임의 목적지를 허용하지 않는다.
- 닥플은 기존 출석 calendar GET의 정상 응답을 확인해 작업 프로필 인증을 판단한다. 일시적 로그아웃 표시나 쿠키만으로 복구 성공을 만들지 않는다. 이미 인증된 작업은 재시도 대기에 걸리는 불필요한 로그인을 시작하지 않는다. 서버 확인은 문서·작업·현재 토큰·한국 날짜에 묶이고 교체된 증거는 되살릴 수 없다. 복구 후 프로필 저장을 마치고 창을 닫는다.
- 닥터빌은 당일 참여 완료/오답을 제품 탐색 전에 읽는다. PC 화면의 같은 제품 중복 링크는 날짜·이름·URL 식별을 대조해 원래 링크로 진행한다. 서로 다른 제품, 날짜 불일치, 알 수 없는 인자 차이는 계속 중단한다. 원래 퀴즈 처리기·하루1회 영속 제출 기록·실제 완료 안내 확인은 유지한다.

## 검증

- Linux, Node24.19.0/npm11.9.0, 고정 Electron45.0.0과 기존 lockfile로 `npm ci`를 실행했다.
- 후속 수정의 Node 회귀는 `node --test --test-isolation=none test/*.test.js` 실제142항목 통과, `npm run check` 통과. 초기 제한 샌드박스의 파일 단위 집계는 제품 항목 통과 수로 사용하지 않는다.
- 원본 background helper를 사용하는 회귀3항목은 기존 코드에서 시간초과·서버 확인0회를 재현했고 수정 뒤 통과했다. SPA/새 문서, 서버401/빈 회원 응답, 제출 전 영속 기록, 복호화/제출/서버 확인 각1회, 진단의 비밀정보 제외와 실패 후 자동 재제출 차단을 검사했다.
- 키메디 수정 시점의 실제 Linux Electron·Xvfb 합성 HTTPS는 개발자 관리 창60·자동 작업20·계정60항목을 통과했다. 후속 수정의 최종 검사는 개발자 관리 창60·자동 작업28·계정80항목을 통과했다. 최종 Windows 묶음의 관리 창도 Linux Electron에서 개발자60/배포55항목 통과했으며 같은 appData 상위 경로의 에디션별 저장소 분리를 확인했다.
- 별도 이전 소스에 새 host 회귀를 적용한32항목 중7항목 실패로 기존 문제를 재현했다. 후속 Node142항목과 Electron 검사는 후다닥의 실제 POST/차단/보호 GET 및 거절·보안 확인, 닥플의401·정상 calendar·프로필 유지·재시도 대기·토큰 교체와 원래 토큰 복원 뒤 증거 부활 금지, 닥터빌의 중복 링크·이미 완료·서로 다른 제품·지난 날짜·1회 제출을 확인한다.
- 컨테이너의 OS sandbox 구성 제약으로 `--container-no-sandbox`는 검사 프로세스에만 사용했다. 제품의 remote sandbox·contextIsolation·TLS 검증은 유지한다. 합성 계정만 사용했으며 Windows DPAPI·실제 사이트 계정의 복구/퀴즈 제출은 이 환경에서 검증하지 않았다.
- 깨끗한 소스136파일을 별도 폴더에 풀어 의존성 설치·Node142·구문 검사를 재현했다. 실제 이전 v9 GitHub ZIP을 다운로드해 SHA·runtime을 대조한 뒤 9→10 패치를 생성했다.

## Windows 재확인과 공개 범위

- 새 빌드의 후다닥·닥플 플러스·키메디 저장 계정 복구, 재시작 후 세션 유지와 실제 실패 원인이 제거됐는지 확인한다. 과거 불확실 시도 제한을 임의로 삭제하지 않는다.
- 사용자는 보고 당일 출석·퀴즈를 모바일에서 먼저 처리했다. PC의 완료 판독과 새 자동 제출을 구분하며, 닥터빌은 미참여일 실제 자동 제출·완료 안내를 재확인한다.
- 모바일 v114 닥터라운지 이식, APK·서명·모바일 릴리스는 변경하지 않았다. PC 에디션 ID·사용자 자료·시도 기록·Electron45.0.0·의존성 해시를 유지한다.
