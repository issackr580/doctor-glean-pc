# 0.1.0-preview.8 로그인 결과 확인

실행파일 소스는 `pc-source-v0.1.0-preview.8`과 각 빌드 manifest의 commit을 기준으로 한다. 계정·세션·시도 이력과 에디션별 앱 ID는 유지한다.

## 동작

- 디톡스 원래 POST 뒤 결과 문서에 로그인/인증 신호가 없으면 고정 보호 목록을 한 번 읽는다. 새로운 로그인 POST는 보내지 않는다. 보호 목록의 실제 인증 근거가 없으면 계정을 저장하지 않는다. 추가 인증·사이트 안내는 자동으로 넘기지 않는다.
- 닥터빌의 공개 로그인 화면에서 입력 형식 오류와 실제 인증 요청을 구분했다. 제출 뒤 manual 안내가 대기 분기에서 무시되던 문제를 고치고 원래 비밀번호 형식 안내를 고정 코드로 표시한다. 실제 Windows 계정의 실패 원인은 추가 관찰로 확인한다.
- 초기 probe/fill과 마지막 결과를 보존하고 동일 관찰은 개수로 합친다. 알려진 두 인증 경로의 요청/응답 개수·HTTP 상태와 콘솔 오류 개수만 진단한다. 값·본문·헤더·쿠키·토큰·전체 URL·오류 원문은 수집하지 않는다.
- 취소 후 미확인과 만료된 cooldown을 구분한다. 이미 저장된8계정과 시도 제한은 지우지 않는다.

## 검증

Node 회귀126항목과 구문 검사를 통과했다. 실제 Electron의 합성 HTTPS 계정41·자동 작업20항목을 통과했고, 빈 POST 결과의1회 GET·POST 재전송0회, 익명 결과의 저장 거부, 입력 형식 안내·인증 요청0회, HTTP503이 인증 성공이 되지 않음, 원래10사이트 처리기와 임시 프로필 해제를 검사한다. 최종 빌드 관리 창 개발자59/배포54도 통과했다. 전체 ZIP·앱 패치와 소스 commit·해시를 대조했다.

제공자 프런트엔드 재생은 공개 정적 자산과 합성 계정만 사용하고 모든 외부 인증 요청을 차단했다. 실제 사용자 계정·Windows DPAPI·적립 성공을 직접 검증한 것으로 표현하지 않는다.

## 배포

배포용은 공개 PC 릴리스, 개발자용은 같은 저장소의 지정 collaborator 전용 Draft다. 7→8 작은 패치는 같은 에디션·동일 Electron/runtime 해시에만 적용한다. 완전 종료 → resources/app 백업 → app 전체 교체 → 버전 확인 순서다. 기존 v7 자산과 태그는 변경하지 않는다.

## 게시 확인

- [배포용 v8](https://github.com/issackr580/doctor-glean-pc/releases/tag/pc-v0.1.0-preview.8)은 공개, 개발자용 v8은 같은 저장소의 지정 collaborator 전용 Draft다. 일반 웹에서 개발자 Draft가404인 것을 확인했다.
- 실행파일 소스 commit은 `3c27096af8ef3b2a37aa71feee94ba086ad18515`이며 소스 태그와 배포 태그가 이 commit을 가리킨다. 게시 확인 문서는 태그 이후에 갱신한 문서다.
- 7→8 패치는 개발자253,158바이트·배포246,493바이트다. 공개 전체/패치/소스 ZIP과 인증한 개발자 패치 다운로드의 SHA를 확인했다. 개발자 전체 ZIP은 서버 digest·크기·ZIP 헤더를 확인했다.
- 두 에디션의 앱 데이터·브라우저·진단 저장소 분리를 대조했고, 배포용에 추가 개발자 기록기·API·화면이 없는 것을 확인했다.
- 기존 PC 릴리스·자산과 Android 원본446파일을 유지했다. Android latest는 v0.7.113 그대로다.

닥터빌·디톡스의 실제 Windows 계정 저장 성공을 완료로 표시하지 않는다. 사용자 재확인 시 새 기록으로 입력 형식·실제 요청/응답·이동·인증 증거를 구분한다.
