## 추가 합성 검사

`scripts/electron-weekend-cases.mjs`를 기존 Electron catalog 검사에 연결했다. `--application`이 주어지면 그 **실제 앱 폴더**의 수집기·vendor·저장소·예약 정책을 동적으로 불러온다. 원본 사용자 DOM을 복사하지 않고 가상의 완전한11월 달력·강의만 사용한다. 가짜 시계는 검사 renderer에만 설정하며 제품의 시간·보안/신청/입장 정책을 바꾸지 않는다.

- 토요일·일요일: 완전한 평일 격자와 다른 날짜의 강의가 있을 때만 두45초 창/원래 GET1회 후 선택일0개를 확인한다. POST0회, 유령 예약0개, 소비0건을 확인한다.
- 날짜 셀 누락·중복·잘못된 요일 헤더·계속 로딩·전부 빈 달력은 선택일 강의 없음으로 확정하지 않는다. 로그인/보안 화면도 빈 목록으로 바꾸지 않는다.
- 토요일의 강의가20초 뒤 또는 GET 재확인 뒤70초에 나타나면 실제 이벤트와 사용자가 선택한 기존 legacy 예약을 유지한다. 주말이라는 이유로 강의를 제거하거나 자동 기능을 새로 켜지 않는다.
- 다음 월요일의 강의를 보존하고 불필요한 빈 날짜 GET을 하지 않는다. 라운지의 월요일 준비 시각과 매일 아침 확인 정책을 대조한다.
- 합성 창을 모두 정리하고 Node·관리 IPC가 없는 기존 원격 창 설정을 사용한다. 실제 로그인·수강 신청·입장/보상 요청은 보내지 않는다.

## 평일에 별도로 남은 확인

주말 자료에는 v31의 실제 자동입장 대상과 실행이 없다. 신청 완료 강의가 있는 평일의 진단으로 **실행 빌드v31 → 대상 ID/일정 확인 → 시도 저장 → 클릭 → 실제 화면 이동 → 재생 → 사이트 출석/보상**을 구분해 확인해야 한다. 특히 이전 빌드에서 실패한 닥터빌18시 대상과 메디게이트 중복 후보, 한미의 cross-origin 재생 미확인은 이번 주말 자료로 해결됐다고 표시하지 않는다. 현재4곳의 전체 목록 범위도 계속 미확정이다.

이번 변경은 검사와 문서만이다. `src/ui/vendor/editions` 및 package/lock의 제품 내용, 계정·선택·예약·필수 시도, updater/feed·서명키, 기존 ZIP/릴리스와 모바일은 변경하지 않았다. 새 제품 버전·리빌드·업데이트를 발행하지 않는다.
